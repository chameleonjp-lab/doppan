# DOPPAN 試遊実施手順

- 文書種別: 試遊プロトコル
- 作成日: 2026-08-09
- 版: 1.0
- 関連文書:
  - [ゲーム制作・プロデュース計画書](./GAME_PRODUCTION_PLAN.md)
  - [品質ゲート定義](./QUALITY_GATES.md)

## 1. 目的

「楽しかった」という感想だけで判断せず、初回理解、操作、狙い、失敗、公平感、上達可能性を同じ方法で記録する。

## 2. 参加者区分

### A. 初見初心者

- DOPPAN未プレイ
- ピンボール経験が少ない、または不明
- 初回体験の確認に使用

### B. 技能型ゲーム経験者

- アクション、スコアアタック、音楽ゲームなどの経験がある
- 上達可能性と操作反応を確認

### C. ピンボール経験者

- 実機またはデジタルピンボール経験あり
- 保持、ショット、戻り、得点戦略を確認

同じ参加者を複数区分へ重複計上しない。

## 3. 段階別人数

| 段階 | 目標人数 | 用途 |
|---|---:|---|
| 技術試作 | 制作者本人 | 物理と入力 |
| グレー版アルファ初回 | 初見3〜5人 | 重大な理解問題 |
| グレー版アルファ対象確認 | 8〜12人 | ショット、得点、公平性 |
| 縦切り版 | 5〜8人 | 視認性、音、演出 |
| リリース候補版 | 初見20人目標 | 公開判断 |

20人に届かない場合は、最低10人の初見結果と限定公開を使う。ただし「大半の利用者が理解する」といった広い主張は行わない。

## 4. ビルド固定

試遊ごとに次を記録する。

- コミットSHA
- 盤面版
- ルール版
- クライアント版
- 日時
- 端末
- OS
- ブラウザ
- 画面方向
- 音設定
- 画面効果設定

同じ比較では、途中でビルドを変更しない。

## 5. 参加者への説明

試遊前に伝える内容:

- 開発中のゲームである
- 正解を当てる試験ではない
- 分からない場合も、そのまま行動してよい
- 画面や操作に問題があれば中止できる
- 個人情報を記録しない
- 自動で外部へプレイ記録を送らない
- 観察記録の利用目的

初回60秒は操作方法を説明しない。安全上の問題と進行不能だけ介入する。

## 6. セッション手順

### 6.1 開始前

1. ビルドと端末を記録
2. 設定を初期化
3. 参加者区分を記録
4. 画面録画の有無を本人へ確認
5. 観察者は助言しないことを再確認

### 6.2 最初の60秒

観察する。

- 最初に触れた場所
- 左右フリッパー理解までの時間
- 発射までの時間
- 誤操作
- 口頭質問
- 球を見失った場面
- 最初に狙った対象
- 安全ショット成功

質問に答えず、「思ったとおりに操作してください」とだけ伝える。

### 6.3 最初の1ゲーム

記録する。

- 各球の時間
- 落下場所
- 各ショットの試行と成功
- 同じ行動の反復
- 球の保持
- クライマックス進行
- 得点内訳
- 介入回数
- 進行不能
- 不具合

### 6.4 終了後質問

順番を固定する。

1. 何を操作するゲームだと思いましたか
2. 一番狙っていた場所はどこですか
3. 得点が高い行動を二つ挙げられますか
4. 球を失った主な理由は何だと思いますか
5. 理不尽に感じた場面はありましたか
6. 次に遊ぶなら何を改善したいですか
7. 1ゲームの長さはどうでしたか
8. 球を見失いましたか。何回くらいですか
9. 演出は結果を理解する助けになりましたか
10. ここで終了する選択は分かりやすかったですか
11. 続けすぎたと感じましたか
12. 自由意見

「楽しかったですか」は最後に聞く。先に聞いて他の回答を誘導しない。

## 7. 観察と本人の感想を分ける

記録欄を分ける。

### 観察事実

- 発射まで12秒
- 右側を5回連打
- 球を2回見失った
- 右アウトレーンから2球落下

### 本人の感想

- 発射方法が分からなかった
- 右側が高得点だと思った
- 中央落下が理不尽に感じた

### 観察者の推定

- 発射表示が弱い可能性
- 右側の発光が強すぎる可能性

推定を事実として扱わない。

## 8. 介入ルール

介入してよい:

- 操作不能
- 白画面
- 健康上の不快
- 誤ってブラウザ外へ移動
- 参加者が中止を求める

介入しない:

- 発射方法に迷う
- 得点目標が分からない
- 球を落とす
- 同じ場所を連打する
- 設定を見落とす

介入した場合、その試遊は初回理解の合否集計から分けて記録する。

## 9. 個人情報と外部送信

- 氏名は不要
- 参加者IDを使用
- 連絡先を試遊記録へ書かない
- 動画を保存する場合は本人の許可を得る
- 公開用動画へ使わない
- プレイ情報を自動送信しない
- 診断情報は本人が内容を確認して共有する

## 10. 再試遊

同じ人の再試遊は、学習後の改善確認に使う。

- 初見人数へ重複計上しない
- 以前のビルドと区別
- どの変更を確認するか一つに絞る
- 改善したか、別の問題が出たかを記録

## 11. 問題の分類

| 分類 | 例 |
|---|---|
| 不具合 | 入力が解除されない |
| 仕様問題 | 発射方法を複数人が理解できない |
| バランス問題 | 安全ショットだけが最高効率 |
| 視認性問題 | 球が発光へ埋もれる |
| 個人差 | 一人だけ配置を好まない |
| 対象外要求 | 3D化してほしい |
| 調査不足 | 原因を再現できない |

## 12. 試遊結果の判断

- 重大な不具合は人数に関係なく修正
- 同じ場所で2人以上が迷った場合は仕様問題候補
- ただし自動的な全面作り直しとはしない
- 品質ゲート未達は不合格
- 少人数の割合は一般化せず、具体行動を重視
- 変更後は同じ質問で再試験
