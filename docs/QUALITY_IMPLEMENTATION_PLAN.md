## Aの採用仕様と受入条件

- 球の寿命は発射から8秒。一律のT98回収は除去し、手動終了と精算60秒上限の強制回収を維持する。
- 自然精算で終端BONUSを使った後の当たりは、加点と三つ揃いを公称0.72秒保持する。120Hzでは87tick（0.725秒）。既存の外れやBONUS開放時間は変更しない。
- 後続当たりの保持中は次保留と自然終了を待つ。手動終了と60秒上限は表示待ちを打ち切り、確定ticketを一度だけ処理する。表示のためにBONUSを追加しない。
- seed1・通常90秒・強さ95（内部0.95）・終端開放ごとの通常発射でT98前後の球IDと寿命、後続当たりの可視時間を検証する。ポーズ、第2・第3開放、手動終了、上限、FIFO、二重払い出し防止も対象とする。
- 球の取りこぼしが直るため得点差を許容する。旧版との全得点一致を求めて不具合を温存しない。

Astra・Highが状態境界を調査し、Sol・Highが0.72秒保持を局所的な表示時間の追加として採用した。技術検査を、実機の操作感や面白さの合格とは扱わない。

## B以降の判断原則

既存1〜64は再発確認用。広い固定256条件を調整用、別の256条件を確認用とし、速い操作と0.3秒・0.6秒遅れを分ける。固定50/80/95、満杯休止、BONUS50/80、閉鎖前の早止めを同じ枠組みで扱う。画面の強さと内部値は既存のプリセットから変換する。

得点の下位10%・中央値・上位10%、初回受理、総時間、満杯時間、拒否理由、開放後に発射した球の入賞を記録する。人工検査の記録だけを開発環境へ保存し、プレイヤーの記録・通信は追加しない。有用な差、ばらつき、下位許容、条件の除外禁止を結果を見る前に固定する。発射と抽選が同じ乱数列を使うため、同一seedでも操作を変えれば抽選列も変わることを明示する。

UIは主状態14px以上を初期目標、操作44px以上・可能なら48pxとし、390×844、402×874、430×932、320×568、横向きで確認する。精算では現在の作業を説明し、結果では受理と拒否を分け、実際の行動に沿う助言を一つ示す。演出は実イベントに限り、球・当たり結果を隠さず、先決めした当落を漏らさない。

計画にないランキング送信、DB変更、アカウント、ゲーム履歴、外部分析は追加しない。表示名必須と既存の狭い互換例外を維持する。iPhoneでの指の動き・見やすさ・聴感・面白さは、節目の人手試遊で別に判断する。
