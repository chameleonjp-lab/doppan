## 1. 運用方法

重要な方針を変更する時は次を記録する。

- 決定ID
- 日付
- 状態
- 決定内容
- 理由
- 比較案
- 影響する文書・実装
- 見直す条件
- 承認者

試験結果を見た後に合否基準を変える場合、変更前の結果を不合格として残す。

状態:

- **決定**: 現行計画の正規方針
- **検証仕様として決定**: 次ゲートで試し、合否により撤回可能
- **仮決定**: 追加調査または明示承認が必要
- **未決定**: 実装へ使わない

### D-004 球をまたぐ進行

- 状態: 検証仕様として決定
- 決定:

## 4. 技術方式の決定

### D-006 入力所有

- 状態: 決定
- 決定: `pointerId`を押し始めた操作へ固定し、解放まで変更しない
- 全解除: pointerup、pointercancel、lostpointercapture、visibilitychange、blur、状態変更

### D-007 描画経路

- 状態: 決定
- 決定: PixiJSのWebGLを本番経路、Canvas完全代替を保証しない、WebGPUはv1.0で使わない

### D-008 物理方式

- 状態: 検証仕様として決定
- 決定: Planck.jsをTPの第一候補
- 見直す条件: 2調整サイクル後も衝突、球を受ける操作、再現性、性能が未達

### D-009 保存

- 状態: 決定
- 決定:
  - 設定と最高得点をブラウザ保存
  - 永久保持を保証しない
  - 進行中ゲームは復元しない
  - 保存失敗でもプレイ継続

### D-010 外部データ収集

- 状態: 決定
- 決定: v1.0では外部テレメトリーを実装しない

### D-024 依存関係の初期候補

- 状態: 検証仕様として決定
- 決定:
  - Node.js 24.18.0 LTS
  - PixiJS 8.19.0
  - Planck.js 1.5.0
  - Vite 8.1.5
  - Vitest 4.1.10
  - Playwright Test 1.61.1
- 確定条件: G1実装で型検査、ビルド、物理試験、ブラウザ試験が成功
- 記録: package.jsonとpackage-lock.jsonへ正確な版を固定

### D-025 物理単位

- 状態: 検証仕様として決定
- 決定: ピクセルをPlanck.jsへ直接渡さず、メートル相当の共通単位を使用
- 初期候補: 盤面横幅9単位、球直径0.30単位前後、フリッパー1.4〜1.7単位
- 見直す条件: TPで接触精度、操作感、数値安定性が未達

### D-026 固定時間と追いつき上限

- 状態: 検証仕様として決定
- 決定:
  - 60または120物理ステップ/秒をTPで比較
  - 最大追いつき時間66ms
  - 60Hz物理は最大4ステップ/描画
  - 120Hz物理は最大8ステップ/描画
  - 250ms以上の差は通常計算へ渡さない
- 見直す条件: iPhone 11 Proで性能未達、ショット再現性に差がある

### D-027 正規ゲームループ

- 状態: 決定
- 決定: 入力反映 → 物理ステップ → 接触バッファ整理 → ショット → ルール → 物理変更予約 → 状態遷移 → 描画の順に統一
- 禁止: 接触コールバック内の物理世界変更、表示操作、直接得点
- 正本: [ゲームエンジン設計](./ENGINEERING_ARCHITECTURE.md)

### D-028 接触バッファと物理変更予約

- 状態: 決定
- 決定:
  - contact参照を保持せず必要値を複写
  - 同一ステップの重複接触を整理
  - 得点イベントへ一意ID
  - 盤面変更を`PhysicsCommandQueue`へ予約し、ステップ後に実行

### D-029 盤面データの分離

- 状態: 決定
- 決定:
  - `TableDefinition`: 変更しない初期定義
  - `TableRuntimeState`: 経路、ゲート、蓄積、覚醒段階
  - `RuleState`: 得点、球数、倍率、モード
  - `PresentationState`: 表示と音
- 理由: 物理、ルール、演出の相互汚染を防ぐ

### D-030 ショット状態機械

- 状態: 決定
- 決定: 球ごと・ショットごとに`Idle → Entered → Validated → Completed → Cooldown`を管理
- 必須: 逆方向、時間切れ、戻り、重複、球終了の失敗遷移

### D-031 ゲーム状態機械

- 状態: 決定
- 決定: 状態変更は`GameStateMachine`だけが行う
- 遷移要求の優先順位: FatalError > WebGLLost > VisibilityLost > BallDrained > ManualPause > 通常遷移
- 必須: 状態遷移表と自動試験

### D-032 安全位置

- 状態: 決定
- 決定: 毎フレーム無条件更新せず、盤面内・非落下・非重なり・安全速度・3ステップ正常を満たす場合だけ更新
- 再発時: 同じ安全位置を無効化

### D-033 WebGL復旧

- 状態: 決定
- 決定: 自動復旧または安全停止の二経路を許可
- 安全停止条件: 白画面なし、全入力解除、物理・得点停止、再読み込み案内
- 理由: ブラウザ側の復旧不能までゲームの不合格にしない

### D-034 資源上限

- 状態: 決定
- 決定:
  - 接触バッファはステップ後に空
  - 物理変更予約256件/ステップ
  - 状態遷移履歴128件
  - 入力履歴512件
  - エラー履歴64件
  - 試遊レポート256KB
  - 同時再生音16
- 確認: 20回再開始後にbody、fixture、joint、イベント購読数が基準へ戻る
