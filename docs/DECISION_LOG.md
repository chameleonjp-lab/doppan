## 1. 運用方法

重要な方針を変更する時は次を記録する。

- 決定ID
- 日付
- 状態
- 決定内容
- 理由
- 比較案
- 影響する文書・実装
- 見直す条件
- 承認者

試験結果を見た後に合否基準を変える場合、変更前の結果を不合格として残す。

状態:

- **決定**: 現行計画の正規方針
- **検証仕様として決定**: 次ゲートで試し、合否により撤回可能
- **仮決定**: 追加調査または明示承認が必要
- **未決定**: 実装へ使わない

## 2. 決定一覧

### D-001 制作目的

- 日付: 2026-08-09
- 状態: 決定
- 決定: カメレオンJPの代表作候補となる公開作品として制作
- 補助目的: スマホ物理ゲーム基盤とAI支援制作工程を残す
- 非目標: v1.0での収益化、ライブ運営、多数盤面
- 見直す条件: ユーザーが別の主目的を明示
- 承認: 計画改善と対応開始の指示をもって現行計画上承認

### D-002 制作段階の名称

- 状態: 決定
- 決定: TP、GA、VS、CCB、RC、v1.0を使用。MVPを工程名に使わない
- 理由: 同じ語が複数完成度を指していた

### D-003 テーマ決定

- 状態: 決定
- 決定: 意味のテーマはGA前、表現のテーマはGA通過後
- 影響: G2、G4

### D-004 球をまたぐ進行

- 状態: 検証仕様として決定
- 決定:
  - 恒久進行、完成目標、基本倍率、クライマックス準備は3球内で保持
  - コンボ、一時倍率、短時間モードは球終了で解除
  - ボールセーブ再発射は進行維持
- 見直す条件:
  - 球1の失敗が全ゲームを決めすぎる
  - 初見が保持・解除を理解できない
  - クライマックス到達率が極端
- 承認: GA検証仕様として承認

### D-005 発射

- 状態: 検証仕様として決定
- 決定: 発射強度と基本スキルショットをTP・GAで検証
- 代替: 固定発射
- 見直す条件:
  - 三段階の強度を再現できない
  - 初見理解を妨げる
  - 攻略価値がない
- 承認: TP・GA検証仕様として承認

### D-006 入力所有

- 状態: 決定
- 決定: `pointerId`を押し始めた操作へ固定し、解放まで変更しない
- 全解除: pointerup、pointercancel、lostpointercapture、visibilitychange、blur、状態変更

### D-007 描画経路

- 状態: 決定
- 決定: PixiJSのWebGLを本番経路、Canvas完全代替を保証しない、WebGPUはv1.0で使わない

### D-008 物理方式

- 状態: 検証仕様として決定
- 決定: Planck.jsをTPの第一候補
- 見直す条件: 2調整サイクル後も衝突、球を受ける操作、再現性、性能が未達
- 承認: TP結果で継続または撤退を確定

### D-009 保存

- 状態: 決定
- 決定:
  - 設定と最高得点をブラウザ保存
  - 永久保持を保証しない
  - 進行中ゲームは復元しない
  - 保存失敗でもプレイ継続

### D-010 外部データ収集

- 状態: 決定
- 決定: v1.0では外部テレメトリーを実装しない
- 見直す条件: 別計画で目的、同意、保存期間、削除方法を承認

### D-011 v1.0範囲

- 状態: 決定
- 決定: 必須、可能な限り、公開後へ分ける
- 正本: [ゲーム制作・プロデュース計画書](./GAME_PRODUCTION_PLAN.md)

### D-012 制作上限

- 状態: 決定
- 決定:
  - GA全面作り直し最大2回
  - テーマ候補最大3件
  - 代表的な仕組み候補3件
  - クライマックス1種類
  - 練習課題最大3件
  - 同一重大問題2調整サイクル

### D-013 正本文書の分担

- 状態: 決定
- 決定:
  - 制作目的・ゲート: GAME_PRODUCTION_PLAN
  - 中心的な仕組み・習熟・表現: CORE_EXPERIENCE_PLAN
  - 技術: IMPLEMENTATION_PLAN
  - 数値合否: QUALITY_GATES
  - 試遊募集・手順: PLAYTEST_PROTOCOL
  - 市場・名称: MARKET_AND_NAME_REVIEW
  - 変更履歴: DECISION_LOG
  - 公開後候補: EXPANSION_IDEAS
- 理由: 重複更新による矛盾を防ぐ

### D-014 制作状況の一枚化

- 状態: 決定
- 決定: `PRODUCTION_STATUS.md`を制作再開時の入口とする
- 更新時期: ゲート、BLOCKER、承認、PR、次作業の変更時

### D-015 代表的な仕組み

- 状態: 決定
- 決定: G2で3候補を比較し、一つを採用
- 必須説明: 操作 → 盤面変化 → 次の判断 → クライマックス
- 現在の仮説: 経路接続型、蓄積と放出型、戻り再構成型
- 見直す条件: G0.5市場比較で重複または制作不能が判明

### D-016 習熟

- 状態: 決定
- 決定: 初見だけでなく、同じ参加者の3〜5ゲーム後をGAで確認
- 不合格兆候: 成功率、試行種類、判断がほぼ増えない

### D-017 球の保持

- 状態: 検証仕様として決定
- 決定: 中心技能候補としてTP・GAで評価
- 分岐:
  - 面白さを増す → 作品約束と必須へ残す
  - 経験者のみ有効 → 上級技能化
  - 初心者を妨げる → 初回案内から除外
  - 全体を不自然にする → 作品約束と必須から除外
- 理由: 物理達成自体を目的化しない

### D-018 縦切り版の範囲

- 状態: 決定
- 決定: 発射、球を受ける操作、中核ショット、戻り、代表的な仕組み、小型クライマックス、四段階演出、軽減設定、WebGL復旧、試遊レポートを統合
- 理由: 簡単な部分だけを本番化して制作リスクを隠さない

### D-019 試遊レポート

- 状態: 決定
- 決定: GAまでに端末内でテキストまたはJSONを生成
- 外部送信: しない
- 個人情報: 含めない

### D-020 試遊募集

- 状態: 決定
- 優先順: 知人対面、限定URL遠隔、経験者個別、限定募集、RC限定公開
- 方針: RCで突然20人を集めず、GA以降に協力者候補を累積

### D-021 アート・音

- 状態: 決定
- 決定: GA前は仮図形、VSで危険部分だけ本番化、音イベント原則12種類以内、音楽最大2状態
- 正本: [中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)

### D-022 品質数値の分類

- 状態: 決定
- 決定: 技術保証値、設計仮説値、プレイヤー観察値へ分ける
- P2: 中心操作へ影響するP2-CoreはCCB以降0件

### D-023 工程別作業予算

- 状態: 決定
- 決定:
  - TP: 基盤PR 1件 + 修正2回
  - G2: 1成果物群
  - GA: 初期盤面PR 1件 + 全面再設計2回
  - VS: 統合PR 1件 + 修正1回
  - CCB: 最大4作業単位
  - RC: 新機能禁止
