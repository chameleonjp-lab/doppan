## 1. 運用方法

重要な方針を変更する時は次を記録する。

- 決定ID
- 日付
- 状態
- 決定内容
- 理由
- 比較案
- 影響する文書・実装
- 見直す条件
- 承認者

状態:

- **決定**: 現行計画の正規方針
- **検証仕様として決定**: 次ゲートで試し、結果により撤回可能
- **仮決定**: 追加調査または明示承認が必要
- **未決定**: 実装へ使わない

試験結果を見た後に合否基準を変える場合、変更前の結果を不合格として残す。

## 2. 作品・制作の決定

- 状態: 決定

### D-003 テーマ決定

- 状態: 決定
- 決定: 意味のテーマはGA前、表現のテーマはGA通過後

### D-004 球をまたぐ進行

- 状態: 検証仕様として決定
- 決定:

### D-007 習熟

- 状態: 決定
- 決定: 初見だけでなく同じ参加者の3〜5ゲーム後をGAで確認

### D-008 球受け・保持

- 状態: 検証仕様として決定
- 決定: 中心技能候補としてG1-BとGAで評価

## 5. ゲームエンジンの決定

### D-017 物理単位

- 状態: 決定
- 決定: CSSピクセルをPlanckへ直接渡さない
- 初期候補: 盤面横幅9物理単位
- 座標: 左下原点、+x右、+y上、反時計回り正、ラジアン

### D-018 更新ループ

- 状態: 決定
- 決定: 独自GameLoopだけが`requestAnimationFrame`を所有
- PixiJS: 自動Ticker・自動描画を停止または不使用
- HMR: 古いループをdispose

### D-019 入力イベントキュー

- 状態: 決定
- 決定:
  - InputEventQueue、InputState、InputOwnershipを分離
  - 押下・解放をsequenceId順で処理
  - 同じ物理ステップ前に押下・解放が来た場合、押下を一ステップ反映してから解放
  - キュー上限超過はP1安全停止

### D-020 ゲームループ順序

- 状態: 決定
- 決定:
  - 入力
  - 物理
  - 接触整理
  - ショット
  - 意味イベント
  - 得点・進行
  - 物理変更
  - 状態
  - 表示状態
  - 描画
  - 音
  の順
- 変更: 表示状態を描画後に更新しない

### D-021 固定時間

- 状態: 検証仕様として決定
- 決定:
  - 60Hzと120HzをG1-Bで比較
  - 最大追いつき66ms
  - 60Hzは最大4ステップ、120Hzは最大8ステップ
  - 250ms以上を通常計算へ渡さない

### D-022 接触イベント

- 状態: 決定
- 決定:
  - SensorTransitionEvent
  - ImpactEvent
  - ContactOccupancy
  - GameEvent
  - ScoringEvent
  を分離
- 接触コールバックで得点、UI、音、物理変更を直接行わない

### D-023 物理変更命令

- 状態: 決定
- 決定: PhysicsCommandQueueをステップ後に実行
- 競合:
  - destroy優先
  - 開閉・有効無効は後の有効命令
  - 破棄済み対象への命令はP1
  - 256件超はP1安全停止

### D-024 状態管理

- 状態: 決定
- 決定:
  - `baseState`
  - `suspensionState`
  - `pendingTerminalEvents`
  を分ける
- 理由: 一時停止で球終了や復帰先を失わないため

### D-025 データ分離

- 状態: 決定
- 決定:
  - TableDefinition
  - TableRuntimeState
  - RuleState
  - PresentationState
  を分ける

### D-026 ショット状態機械

- 状態: 決定
- 決定: Idle → Entered → Validated → Completed → Cooldown
- 逆走、戻り、時間切れ、重複を失敗として管理

### D-027 Planck初期設定

- 状態: 検証仕様として決定
- 決定:
  - 球はdynamic、bullet有効
  - sleep無効を比較
  - フリッパーはdynamic + revolute joint + motor
  - 物理解法初期候補8/3
  - 発射は決定的な初速またはimpulse

### D-028 安全位置

- 状態: 決定
- 決定: 連続3ステップ正常などの条件を満たす時だけ更新
- 同じ位置で二回異常なら無効化

### D-029 runIntegrity

- 状態: 決定
- 決定: 時間切り捨て、入力あふれ、命令あふれ、状態不整合を記録
- 無効なゲームは結果表示可、自己最高へ保存不可

### D-030 資源寿命

- 状態: 決定
- 決定: AppLifetime、GameLifetime、BallLifetime、EffectLifetimeを分ける
- 再開始20回で寿命別の基準値へ戻ることを確認
