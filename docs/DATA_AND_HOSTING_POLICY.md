## 1. この文書の役割

本書は、DOPPANで保存するもの、保存しないもの、外部へ送るもの、GitHub Pagesを使い続けられる条件の正本である。

本書と既存文書の記述が衝突する場合は、本書を優先する。

次の既存記述は、本書の決定により失効する。

- 最高得点、自己最高、戦績、プレイ履歴、プレイ回数を保存する記述
- `score`、`bestScore`、`history`などのゲーム記録用保存キー
- ゲーム記録の保存失敗、移行、破損を正式版の完成条件にする記述
- 正式版1.0で個人アカウント、ログイン、利用者識別子を設ける可能性を残す記述
- ランキング、Supabase、外部分析を当然の公開後機能として扱う記述
- GitHub Actionsを実行時サーバー、定期的なゲーム処理、配信網として使う案

古い文言の機械的な整理は後続の文書整合PRで行えるが、実装判断では本書を直ちに適用する。

## 2. 正式なデータ方針

### 2.1 保存しないもの

DOPPANは、次を端末にも外部サービスにも保存しない。

- プレイヤー名
- メールアドレス
- パスワード
- 個人アカウント
- ログイン状態
- 永続的な利用者識別子
- 端末指紋
- IPアドレスを利用した識別情報
- 今回の得点
- 最高得点
- 得点内訳の自己最高
- 勝敗、戦績
- プレイ履歴
- プレイ回数
- 初回プレイ日、最終プレイ日
- 継続日数
- ランキング記録
- 進行中ゲーム
- リプレイ、ゴースト
- 行動分析用の操作履歴

ゲーム結果画面には、現在のプレイで得た得点と内訳を一時的に表示できる。ただし、再挑戦、再読み込み、タブ終了、ブラウザ終了後へ引き継がない。

### 2.2 プレイ中だけ保持するもの

次は、一回のゲームを成立させるためにブラウザのメモリ内だけで保持する。

- 得点
- 残り球
- 球をまたぐ盤面進行
- 倍率
- コンボ
- クライマックス準備
- 現在の物理状態
- 入力状態
- 診断情報
- 今回の結果文

ゲーム終了後に結果画面を閉じるか再挑戦した時点で、次のゲームへ持ち越さない。再読み込み、タブ終了、強制終了から復元しない。

### 2.3 端末内保存を許可するもの

個人の記録ではなく、遊びやすさを保つための設定だけを端末内へ保存してよい。

- 音の有無と音量
- 画面揺れの軽減
- 点滅、粒子、軌跡の軽減
- 高コントラスト
- 初回操作案内の表示設定

設定には、氏名、得点、日時、回数、利用者ID、端末IDを含めない。

設定保存が使えない場合は安全な初期値で起動し、ゲームを止めない。設定を保存しない利用方法も正常動作として扱う。

設定キーは環境別に分ける。

```text
doppan:development-preview:settings:v1
doppan:production:settings:v1
doppan:test:settings:v1
```

汎用の保存部品が存在する場合も、正式版1.0では設定オブジェクト以外へ使用しない。

## 3. 外部通信と外部サービス

### 3.1 正式版1.0で行わないもの

- 認証サービスへの通信
- データベースへの通信
- スコア送信
- プレイ開始、終了の通知
- ランキング取得
- 外部分析サービスへの送信
- 広告配信
- 行動追跡
- ユーザー生成コンテンツの投稿
- 決済
- 有料機能の購入
- サーバー上のゲーム処理

ゲーム本体は、GitHub Pagesから静的ファイルを読み込んだ後、プレイヤーのブラウザ内で動作する。

画像、音声、JavaScriptなどのゲーム素材以外を、DOPPANのコードから外部へ送信しない。

GitHub自体が配信基盤として保持するアクセス記録は、DOPPANのアプリケーションが収集・利用する記録とは分けて扱う。DOPPAN側ではそれを利用者識別、ランキング、行動分析へ使用しない。

### 3.2 将来変更する場合

次のいずれかを追加する場合は、本書を無断で拡張せず、別の計画判断を必要とする。

- アカウント
- ログイン
- 名前登録
- スコア保存
- ランキング
- プレイ人数・回数の実測
- 広告
- 寄付以外の収益化
- 決済
- 外部分析
- 対戦用サーバー
- ユーザー投稿

変更前に、必要性、保存期間、削除方法、利用者説明、不正対策、費用、ホスティング規約を再検証する。

## 4. GitHubだけで運用する構成

正式版1.0の構成を次へ固定する。

```text
GitHubリポジトリ
  ├─ ソースコード
  ├─ 計画書
  └─ GitHub Actions
       ├─ 型・静的検査
       ├─ 単体・物理・ブラウザ試験
       ├─ 本番ビルド
       └─ 承認後のGitHub Pages配置

GitHub Pages
  └─ HTML / CSS / JavaScript / 画像 / 音声の静的配信

プレイヤーのブラウザ
  ├─ 物理計算
  ├─ 得点計算
  ├─ 一回のゲーム状態
  └─ 個人識別を伴わない設定だけを任意保存
```

次は使用しない。

- Supabase
- Cloudflare Workers
- Cloudflare D1
- Firebase
- 独自サーバー
- 認証基盤
- 外部データベース
- 外部分析基盤

## 5. GitHub Pages規約への適合判断

### 5.1 現在の判断

2026年8月10日時点のDOPPANは、次の条件を満たす限り、GitHub Pagesが想定する「個人または組織のプロジェクトを紹介する静的ページ」の範囲に入る可能性が高い。

- 無料のブラウザゲーム
- 静的ファイルだけを配信
- 個人アカウントなし
- 利用者データ収集なし
- 決済なし
- 商取引なし
- 商用のオンラインサービスとして運営しない
- GitHub Actionsは開発、試験、ビルド、公開だけに使用

ただし、規約適合の最終判断権はGitHubにある。本書はGitHubによる将来の判断を保証しない。

公式確認先:

- GitHub Pages limits: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits
- GitHub Terms for Additional Products and Features: https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features

### 5.2 禁止境界

GitHub Pagesでは、オンライン事業、電子商取引、商取引を主目的とするサイト、商用のSoftware as a Serviceを無料ホスティングする利用が禁止されている。

そのため、正式版1.0では次を入れない。

- 商品購入
- 有料会員
- 有料アイテム
- 決済情報送信
- 商取引を主目的とする導線
- 企業向け有料サービスとしての提供

寄付やクラウドファンディングの導線は規約上許容例があるが、DOPPAN正式版1.0では必要機能にしない。

### 5.3 GitHub Actionsの禁止境界

GitHub Actionsは、DOPPANの開発、試験、ビルド、配置にだけ使う。

次の使い方を禁止する。

- ゲーム中の要求を受けるサーバー代わり
- 定期実行によるランキング集計
- 常時稼働処理
- 配信網の代用
- サーバーレスアプリの代用
- リポジトリの開発、試験、配置と関係しない処理

## 6. 想定規模と無料運用の上限

### 6.1 運用想定

- 1日あたり利用者: 100人
- 1日あたりプレイ: 200回
- 1か月あたりプレイ: 約6,000回
- 初回転送目標: 3MB以内
- 遅延素材を含む総容量目標: 10MB以内

### 6.2 通信量の安全側計算

毎回すべての10MBを読み直す厳しい条件では、次となる。

```text
10MB × 200プレイ × 30日 = 約60GB／月
```

GitHub Pagesの公表上限は、公開サイト1GB以内、月間通信量は100GBの柔軟な上限である。

現在の60GB試算は公表値を下回るが、100GBは課金契約上の保証枠ではない。キャッシュ不使用、素材増加、アクセス集中、第三者からの大量アクセスにより余裕が減る。

### 6.3 内部停止線

正式公開後は、次のいずれかに該当したら素材追加と公開更新を止め、配信方式を再評価する。

- 初回転送が3MBを継続的に超える
- 総容量が10MBを超える
- 月間転送量の見積もりが70GBを超える
- GitHubから帯域、負荷、利用方法について警告を受ける
- HTTP 429などの制限が反復する
- Pagesサイトが1GBへ近づく

DOPPAN自身はアクセス記録を保存しないため、正確な転送量をゲーム内分析で測らない。GitHubが提供する範囲の管理情報と、素材容量からの安全側見積もりで判断する。

## 7. G7公開前の規約確認

一般公開承認前に、次を再確認する。

- GitHub PagesとGitHub Actionsの公式規約が変更されていない
- DOPPANが静的なプロジェクト展示の範囲にある
- 決済、広告、アカウント、外部データ収集がない
- Actionsが開発、試験、ビルド、配置だけを行う
- 公開サイトが1GB未満
- 初回3MB、総容量10MBの目標内
- 想定通信量が内部停止線以下
- 正式版に秘密情報がない
- 規約判断に疑義が残る場合は、公開前にGitHub Supportへ確認する

この確認を通過しない場合、GitHub Pagesへの正式公開を承認しない。

## 8. ホスティング変更条件

次の場合は、GitHubだけでの運用を守るために機能を削るか、公開前に別ホストへ移す計画を作る。

- GitHubから移行を求められた
- GitHub Pagesの規約変更で対象外になった
- 商取引や商用サービスへ変わった
- 100GBの柔軟な上限へ継続的に近づいた
- 動画、大容量音声、ユーザー投稿を追加した
- サーバー処理が必要になった
- アカウント、記録保存、ランキングが必要になった

自動的に別サービスを追加しない。ユーザー本人の承認後に、費用、規約、移行手順を新しい計画書へ記録する。

## 9. 実装上の必須規則

- ゲームルールの状態はメモリだけに置く
- `localStorage`、`IndexedDB`、Cookieへゲーム記録を書かない
- 設定保存の型へ得点、回数、日時、利用者IDを追加しない
- 外部分析ライブラリを依存へ追加しない
- 認証用ライブラリを依存へ追加しない
- 結果共有は、現在のメモリ上の結果文を利用する
- 共有失敗時も保存や外部送信へ切り替えない
- 診断レポートは端末内生成と利用者による明示コピーに限定する
- 自動送信を行わない
- ネットワーク要求は同一オリジンの静的素材取得を基本とする

既存の`src/storage/save-storage.ts`は、正式版1.0では設定保存専用へ用途を狭める。ゲーム記録用の汎用保存として公開しない。設定実装PRまでに、名称、型、試験を本書へ合わせて修正する。

## 10. 合格条件

正式版1.0では、次を自動試験またはレビューで確認する。

- アカウント作成画面がない
- ログイン画面がない
- 名前入力がない
- 得点・最高得点・戦績の永続保存がない
- ランキング通信がない
- 外部分析通信がない
- 外部データベース依存がない
- 再読み込みで進行中ゲームが復元されない
- 設定保存が使えなくてもゲームを開始できる
- 設定データへ個人情報、得点、日時、回数、識別子が入らない
- GitHub Actionsが開発、試験、ビルド、配置以外を行わない
- G7で規約と容量を再確認する

---

## 11. 決定の要約

> DOPPAN正式版1.0は、個人アカウント、ログイン、名前、永続的な利用者識別子、スコア、最高得点、戦績、プレイ履歴、プレイ回数、ランキング、外部分析を持たない。ゲーム状態は一回のプレイ中だけブラウザのメモリへ置き、音・表示・アクセシビリティの非個人設定だけを任意で端末内保存する。公開と自動試験にはGitHub PagesとGitHub Actionsだけを使い、静的な非商用プロジェクトの範囲、容量、帯域、Actions用途をG7で再確認する。
