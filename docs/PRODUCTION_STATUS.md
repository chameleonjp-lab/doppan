## 3. データ非保存の決定

正式版1.0は、ゴッドフィールドのような個人アカウントを作らず、個人の記録も保存しない。

保存しないもの:

- プレイヤー名、ログイン、アカウント、永続的な利用者識別子
- 得点、最高得点、得点内訳の自己最高
- 戦績、プレイ履歴、プレイ回数、継続日数
- ランキング、リプレイ、ゴースト
- 外部分析用の行動履歴

一回のゲーム状態はブラウザのメモリ内だけで保持し、再挑戦、再読み込み、タブ終了後へ引き継がない。

端末内保存を許可するのは、音、画面効果、高コントラスト、初回案内などの非個人設定だけとする。設定保存が失敗してもゲームを継続する。

既存の`src/storage/save-storage.ts`は、ゲーム記録用の汎用保存として使わない。設定実装PRまでに、設定専用の名称、型、試験へ修正する。

## 4. 完成前のGitHub Pages方針

- GitHub PagesをiPhone確認に使用
- 完成前はURLをREADME、SNS、公開サイト、記事へ掲載・案内しない
- ユーザー本人だけがGitHub Actionsなどから確認URLを開く
- 本番ルートへ未完成ゲームを置かない
- 確認ページは信頼済みブランチ一件だけ
- 検索除外を設定
- GitHub Pagesは公開URLであり、秘密性やアクセス制限は保証されない
- 第三者へ確認URLを配布しない
- `main`への取り込みだけでは正式版を公開しない
- G7後の手動承認で正式公開

試遊で第三者へURLを送らない。完成前の試遊は、原則としてユーザー所有端末を使った対面または管理下の確認で行う。

正式版1.0は、無料の静的ゲーム、商取引なし、決済なし、アカウントなし、利用者データ収集なしを維持する。GitHub Actionsは開発、試験、ビルド、配置だけに使い、実行時サーバー、定期集計、配信網として使わない。

## 5. 現在のBLOCKER

### G0.5

調査成果物は完了。10作品を比較し、DOPPANの仮の固有価値を「成功ショットで戻り道を組み替え、次の狙いを変える」と記録した。

残るのは正式名称と権利の確認である。`DOPPAN`は開発名として仮採用し、G7前にJ-PlatPat、WIPO、主要ストア、ドメイン、SNSを再確認する。

### 公開・端末確認の繰り延べ事項

1. `github-pages` Environmentの必須reviewer、deployment branch rule、`DEVELOPMENT_PREVIEW_ENABLED`を確認していない
2. G3 / GAの最新mainを使うPages workflowの実配置を確認していない
3. 2026-08-12の公開URL確認では、ルートがVite変換前の`/src/main.ts`を直接参照し、画面が「初期化中」のまま停止した。これはゲームコードの合否ではなく、Pagesの配信元がビルド成果物になっていない問題である
4. 正しい成果物はルートに案内だけを置き、ゲームを`/_preview/current/`へ置く。ルート案内、プレビュー、ビルドSHAを実URLで確認していない
5. G1-Aマージ後の確認ページ終了処理を確認していない
6. iPhone Safariの表示、保存、二本指、体感遅延、発熱はGA開始時にまとめて確認する

2026-08-14の読み取り確認では、Pagesのルートは`2026-08-11`更新の旧G3 / GAゲーム画面を返し、`/_preview/current/`と`robots.txt`は404だった。Pages APIのSourceも旧`agent/ga-clarity-pages-sync`を示しており、`main`を対象にした`Development preview`の手動実行記録は確認できなかった。したがって、PR #20のマージだけではPages確認完了とは扱わず、GitHub側の手動workflow実行後に再確認する。

これらはG3 / GAの技術縦切りを取り消すものではない。Pagesの設定・手動配置確認が終わるまで、公開確認とGAの人手試遊は開始しない。

### G1-B

PR #8のマージにより通過扱い。G1-B時点では球受けから安全ショットへつながる通常プレイ経路が未成立だった。現在のG3 / GA作業では、最大発射から右フリッパーへ戻る既存経路を使い、実入力で`L0` / `R0`へ到達する下部安全ショットを検証する。球受け・保持は引き続き作品の必須約束に戻さない。

### G2

PR #10のマージにより、自動ゲート上は通過扱い。戻り再構成型、固有動詞「つなぎ直す」、ショットマップv0.1、次目標と戻りゲートの切り替えを仮図形へ実装した。G3 / GAで初見理解、反復時の上達、戻り変化の実効性を検証する。

### G3 / GA

PR #11のマージとCI Run #24で、G2の仮図形を3球の一回のゲームへ接続する技術縦切りを確認した。球終了でコンボを解除し、得点と経路進行はゲーム内で保持する。3球目終了後に結果を表示し、新しいゲームで初期化する。試遊レポートはブラウザのメモリ内で生成し、表示または明示的なコピーだけを許可する。

自動検証は技術的な縦切りの合否を扱う。初見15秒理解、3〜5ゲーム後の上達、片側連打の支配性、iPhone Safariの操作感、面白さは未判定であり、Pagesの確認後に管理端末の対面試遊で判定する。

PR #16で、開発者用表示の隔離、プレイヤー向けHUD、開始・結果画面、盤面内操作、現在目標の表示、安全・中核・危険ショットの読める差をマージした。

ただし、PR #16までの自動試験には次の欠落があった。

- 物理統合試験は球をセンサーへ直接移動し、発射・フリッパー入力を経由していなかった
- 発射レーンと`R0`センサーが重なり、フリッパー未入力でも成功し得る配置だった
- ブラウザ試験は発射とフリッパー作動を別々に確認し、得点・進行・戻り変更までつないでいなかった

本作業単位では、安全ショットを発射レーン外の実軌道へ移し、最大発射と画面操作相当のPointer入力だけで`L0` / `R0`を成立させる。PR #17で60Hz / 120Hz、各10個の固定入力条件、発射だけ・無関係なフリッパーの負の対照、得点・進行・次目標・戻りゲートを自動確認した。PR #18で対応フリッパーへの実到達・実衝突、PR #19でR0返球ガイドを成功後だけ有効化した同側Pointer入力後の上向き速度まで確認した。これは物理的な到達可能性の自動証明であり、人が初見で10回中8回成功できること、左右の選択理由、端末上の操作感、面白さの合格ではない。
