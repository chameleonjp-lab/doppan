## 1. この文書の決定範囲

本書は、DOPPANの中心体験を、従来の「3球で戻り経路をつなぎ直すピンボール」から、短い期待と結果の循環を繰り返すパチンコ型ゲームへ組み替えるための正本ドラフトである。プレイヤーが球を発射して、空きのある中央へ入賞すると保留が増え、予告と図柄変動が始まる。通常停止またはリーチから当落を示し、大当たりなら払い出しと有限のRUSH継続判定へ進む。90秒後は、受理済みの結果を捨てずに精算して一ゲームを終える。

2026-09-05のユーザーによる根本変更の指示は、従来の中心体験、3球制、ショット接続順、クライマックス到達条件と、それらを前提にしたG2 / G3 / GAゲートを上書きする。旧実装の技術的な検査実績は履歴として残すが、新しいゲームの面白さや完成を証明する根拠にはしない。

PixiJS、Planck.js、固定ステップの単一ゲームループ、入力解除、安全停止、Pagesのプレビュー分離は再利用候補として残す。金銭賭博、有料通貨、アイテム獲得型ガチャ、ログイン報酬、強制再挑戦、広告、決済は導入しない。プレイヤーが「もう一度遊ぶ」を自分で選ぶまで新しいゲームを始めない。

本書でいう期待、結果差、達成、逆転はプレイ中の情報設計とゲーム状態を指す。神経伝達物質の分泌などの生理作用は測定も保証もしない。

## 2. 当初資料から抜けていたもの

2026-08-09の企画分析は、入賞と保留から始まり、先読み、保留変化、特殊ゾーン、音・光・振動、リーチ、上位発展、チャンスアップ、PUSH、失敗、復活、大当たり、RUSH継続へ進む段階構造を整理していた。要点は強い当たりだけではなく、結果までの途中に小さな予兆、進捗、分岐、失敗後の巻き返しを置くことだった。

`d8fd997`時点の従来実装は、この構造を中心ルールへ反映できていない。以下は旧実装に対する観察であり、新しいパチンコ型実装は本書に基づくPR #32でマージされた。マージや自動検査の成功を、面白さの確認済みまたは完成済みとは扱わない。

- `src/graybox/graybox-runtime.ts`は、`L0 / R0`から`C1`までの成功順を固定し、成功のたびに得点、次目標、戻りゲートを即時更新する。結果を待つ保留、予兆、変動、リーチ、当落の差はない。
- `C1`成功後は`climaxState`が`active`になるだけで、時間制の払い出し口、ボーナス中の追加得点、継続判定、終了処理へ接続していない。
- `src/game/ga-session.ts`は一ゲーム3球を固定し、3球目の落下で結果へ移る。期待状態を繰り返す時間制ゲームではない。
- `src/table/graybox-table.ts`の`L2 / R2 / C0 / C1`は上部の仮センサーであり、旧`docs/PRODUCTION_STATUS.md`にも実プレイヤー経路が未確認と記録されている。従来のC型中心体験は、人手の面白さ判定前だった。
- 現在の結果画面は最終得点、旧進行、旧クライマックス、共有、ランキングを表示するが、ゲーム中の保留、抽選状態、失敗回数、復活保証、RUSH状態を示さない。

このため、旧C型へ演出だけを追加しても根本問題は解決しない。ルール状態を入賞・保留・抽選・ボーナス中心へ置き換え、表示をその状態の読み出しにする。

## 3. 新しい一ゲームの仮仕様

以下の数値は最初の統合版を作るための仮値であり、確定値ではない。実装担当が物理到達率と自動検査結果を得た後、本節を更新できる。

| 項目 | 仮値 | 意図 |
| --- | ---: | --- |
| 通常時間 | 90秒 | 一回で期待と結果の循環を複数回見せる |
| 初期球 | 80球 | 長押し発射の有限資源 |
| 発射間隔 | 0.20秒以上 | 入力を受けた連射の上限。性能検査後に調整 |
| 1発の得点変化 | -10点 | 発射に判断と損失を持たせる |
| 中央入賞 | 保留受理時だけ+50点、+3球 | 得点と球の払い出しを保留生成と一体にする。保留満タン時と90秒後は+0点、+0球で回収 |
| 左右の副入賞 | +20点、+2球 | 保留を作らない小さい払い出し口 |
| 保留上限 | 4件 | 盤面と抽選の二つの進行を読みやすく保つ |
| 基本大当たり率 | 1/5 | 90秒内で見せ場を検証する仮率 |
| 巻き返し | 5回連続で外れた後、次の受理保留を大当たりにする | 不運だけで見せ場が消えることを防ぐ。メーターを常時表示 |
| 大当たり | +1,500点、+30球 | 初回確定時に一度だけ加算し、通常入賞と明確な結果差を作る |
| アタッカー開放 | 6秒 | 大当たり後にプレイヤーが追加得点を狙う短い操作区間 |
| アタッカー入賞 | +100点、+5球 | BONUS中の払い出しを得点と残り球へ反映する |
| RUSH継続 | 各1秒、1/2 | 初回を含め合計最大3区間。継続判定は最大2回 |

基本大当たり率1/5へ5連続外れ後の保証を加えると、独立抽選だけの1/5より実効大当たり率が上がる。抽選一件当たりの理論値は約27.1%、大当たり一件までの平均保留数は約3.689件となる。初期80球を払い出しなしで全部発射した減点は800点であり、大当たりの+1,500点がこれを上回る。報酬対象の入賞は球も払い出すため、仮値のままでは抽選運と大当たり後の追加発射数がランキングを強く左右する可能性がある。統合版では値を隠さず、後述の分布検査と人手試遊で調整する。

### 3.1 通常状態

プレイヤーが発射操作を続けている間だけ、球数と発射間隔の範囲内で球を出す。1発ごとに10点を引く。操作を離せば発射を止められる。自動で全弾を消費せず、ゲーム中の一時停止も可能にする。

画面の強さは50・80・95の3段階、初期値は95とする。スライダーの内部値は0〜2のインデックスで、画面表示と読み上げには実際の強さを使う。左右キーは1段階ずつ移動し、初期値とsessionのreset値を共有定数で95にそろえる。強さに対する入賞率は単調ではなく、前回の64seed×5強度では35と65にSTARTへ届かないゲームが多かったため、通常操作からその帯域を外す。物理の連続値API・発射曲線・盤面・抽選は変えず、全強度の物理的な偏りが解消したとは扱わない。

持ち玉0、盤上球0、保留0、変動なし、BONUS/RUSHなしがすべて成立した時は、90秒を待たず「持ち玉終了」として結果へ進む。残る保留や継続権がある間はこの早期終了を行わない。

中央入賞は、保留に空きがあり新しいticketを受理できた時だけ、保留一件、50点、3球を同時に加える。保留が4件ある時と90秒後はticketを受理せず、中央へ入った球を+0点、+0球で回収する。HUDと盤面に「保留満タン・中央払出なし」または「精算中・新規保留なし」を即時表示し、入賞の見落としや得点不具合に見せない。左右の副入賞は保留数に関係なく20点と2球を加え、保留を生成しない。

この規則により、通常時は保留が満タンなら発射を止めて変動を待つ判断が生まれる。BONUS中は、通常保留の変動が止まっていても、開いているアタッカーへ入れば100点と5球を得られるため、発射を続けて得点口を狙う理由が残る。

### 3.2 保留と抽選

保留はFIFOで消化する。保留が受理された時点で、単一の乱数源から当落、図柄、リーチの有無を一度だけ確定する。表示開始、PUSH、描画フレーム数、端末性能、ポーズ、ページの可視状態によって再抽選しない。大当たり保留を受理した時点で、その大当たりに属する二つのRUSH継続結果も同じ乱数源から先に確定する。「次の3保留がRUSH抽選になる」規則は採用しない。

本番では一ゲームに一つのseedを作り、ゲーム中だけメモリに置く。テストではseedまたは乱数関数を注入し、同じ入力とseedから同じ結果列を再現できるようにする。ゲーム記録やseedを端末へ永続保存せず、ランキングへ送信しない。

当たり保留は同じ図柄を三つそろえる。外れ保留は左右図柄を独立に作り、左右が偶然一致した時だけリーチへ進め、中央は異なる図柄で止める。外れを惜しく見せるための別確率を加えない。参考実装の18%の故意の外れリーチは採用しない。

5連続外れ後は、HUDに「次回復活確定」と表示したうえで、次の受理保留を保証保留として当たりへ固定する。保証保留だけは中央図柄を仮の外れ位置へ一度停止し、再始動して三つそろえる。大当たり得点と30球は、再始動後にwinが確定した時点で一度だけ加算する。仮停止時と再始動時に重複加算しない。保証の存在を隠して偶然の逆転のように扱わない。

### 3.3 予告、変動、リーチ、PUSH

最小統合版は、通常保留と保証保留のcueを色だけでなく形と文言でも区別する。保証へ近づく状態は`0 / 5`から`5 / 5`のメーターで示し、結果を変えない第三の保留種別を作らない。待機中に新しく受理した保留は0.36秒のpreviewを挟む。すでに保留欄へ表示されている後続保留はFIFOで直接変動へ進む。保証保留のcueは、画面で5回目の外れを開示するまで通常保留と同じ表示にする。演出状態は少なくとも`idle`、`preview`、`spinning`、`reach`、`reveal`、`revival`を区別し、状態遷移の時間をルール層で管理する。

これにより、最小統合版でも「入賞の反応」「保留が増えた進捗」「保証へ近づく先読み」「自然リーチ」「当落」「保証復活」「大当たり」「RUSH」の中間段階を持つ。惜しさは、左右図柄が実際に一致した時と保証メーターが実際に進んだ時に返し、結果と関係のない強い煽りを足さない。特殊ゾーン、上位発展、複数種のチャンスアップは、この縦切りの理解を確認してから追加を判断する。

後続対応では、PUSHを結果に介入しない「演出の合図」として実装する。左右停止後の全リーチで、変動開始から1.55秒以上3.1秒未満の間に一度だけ受け付ける。当たりだけでなく外れリーチでも同じ条件を使い、受付の有無から当落を漏らさない。snapshotは`hidden / ready / accepted`、イベントは結果情報を含まない`spin-push`とする。

PUSHは乱数、ticket、図柄、経過時間、確定時刻、得点、球、BONUSを変更しない。通常リーチは入力の有無にかかわらず3.1秒で開示する。保証復活は3.1秒で仮停止へ入り、既存の0.25秒＋0.4秒を経て3.75秒で確定する。早押し、連打、受付期限後、ポーズ中の入力は追加効果を持たない。精算中も受理済みリーチの受付は有効だが、手動終了と精算上限は従来どおり即時精算を優先する。

操作列は「発射／PUSH／終了」の常設3列とし、PUSHで盤面やLCD、主要入力を隠さない。押下直後は「PUSH受付！ 結果を待とう。」、受付済のラベル、静的な枠色、音ON時だけの短い合成音で応答する。「結果を見る」「結果を開く」とは表現しない。タッチとネイティブボタンのEnter／Spaceで操作でき、自動フォーカスや発射保持の解除は行わない。画面効果軽減・音なしでも受付済を判別できる。ヘルプへ「PUSHは演出の合図。押さなくても当落・表示時刻は同じです。」と明記する。

最小統合版は、すべての保留に長い演出を付けない。通常外れは短く、自然なリーチ、大当たり、保証復活だけを段階的に長くする。盤上の球と主要入力を演出で隠さない。

### 3.4 大当たり、払い出し、RUSH

大当たり確定時に1,500点と30球を一度だけ加え、最初のBONUS区間としてアタッカーを6秒間開く。アタッカー開放中の入賞一件ごとに100点と5球を加える。開放時間、獲得点、現在区間をHUDへ`RUSH 1 / 3・残り5.8秒`のように常時表示する。BONUS中は通常保留の変動を停止し、RUSH表示を通常変動で隠さない。

各区間の開放終了後、1秒間の継続判定を表示する。大当たり受理時に確定済みの1/2判定が成功なら次の6秒区間へ進み、失敗なら通常状態または精算へ戻る。BONUS区間は初回を含め合計最大3区間、継続判定は最大2回である。継続しても大当たりの1,500点と30球を再加算しない。

この1秒間は、内部の先決め結果を画面のタイトル・案内・読み上げへ出さず、「継続判定」と表示する。既存の`rush-continue`または`rush-end`で実際の状態が変わった時に、継続または終了を初めて告知する。内部の抽選時刻、結果、1秒の長さは変更しない。

90秒の時計はBONUS中も進む。BONUS区間では残り球を発射できる。ポーズまたは画面非表示による停止中は、通常時間、BONUS時間、継続判定時間のいずれも進めない。

RUSHは同じゲーム内の有限なボーナス状態であり、次ゲームの自動開始、ログイン継続、日次報酬、購入、換金、アイテム抽選へ接続しない。

### 3.5 90秒終了と精算

通常時間が0になったら通常発射と新規ticketの受理を止め、直ちに結果画面へ飛ばさない。既にBONUS中ならそのBONUS系列を最大3区間まで完走し、区間中は残り球を発射できる。BONUS中でなければ受理済みticketを順に精算し、最初に判明した大当たりだけを終端BONUSとして最大3区間まで完走する。終端BONUS中も残り球を発射できるが、中央入賞から新しいticketは作らない。同じ精算中の後続大当たりは1,500点と30球を一度だけ加算し、新しいBONUS系列を重ねない。

90秒後の精算には60秒の絶対上限を設ける。上限到達または`manualFinish`では、未表示の確定ticketを捨てず、確定済みの当落を即時に得点と球へ反映して結果へ移る。保証ticketの仮停止や通常演出は省略できるが、当落を引き直さず、win一件につき大当たり得点と30球を一度だけ加算する。上限到達後に新しいBONUSを始めず、すでに得たアタッカー入賞分だけを結果へ含める。

### 3.6 重要な案内と盤面の表示

PR #33までの表示では、イベントを届いた順に案内欄へ書いていたため、リーチ・PUSH・大当たりの案内が副入賞や球回収ですぐ消えることがあった。また、大当たり中も中央入賞口の枠が強く光り、開いた得点口と注意を取り合っていた。表示改善では、実際の状態から案内の優先度と強調する場所を決める。

| 状態 | 案内欄に残す情報 | 盤面で強調する場所 |
| --- | --- | --- |
| 通常・保留に空きあり | 発射案内と通常入賞の結果 | 中央入賞口。得点と払い玉を短く示す |
| 保留満タン・通常の精算 | 満タンまたは新規保留なしという現在の状態 | 新しい抽選を狙う点灯を止める |
| リーチ・保証復活 | リーチ・PUSH受付など、その変動に属する案内。通常入賞や回収では消さない | 液晶の枠を段階に応じた形で区別する |
| 得点口が開いている間 | 大当たり・継続、または得点口入賞の+100点・5玉 | 得点口の外側に金色の角枠と方向マーカーを出す |
| 継続判定中 | 中立な判定中の案内 | 液晶の枠。得点口は閉鎖と表示する |
| 継続判定が終わった時 | 実際に確定した継続・終了を告知する | 実際の開閉状態へ切り替える |

中央入賞口の報酬表示は保留受理の可否に合わせ、満タン時・通常時間終了後に+50点・3玉を得られるように見せない。BONUS中も保留受理が可能な場合があるため、中央入賞口を無効とは断定せず減光に留める。得点口は実際に開いている時だけOPENと払い出しを示し、判定中を含む閉鎖時はCLOSEDと示す。

告知はゲームの状態に合わせて保持・解除し、別の時計や演出用スケジューラを追加しない。ポーズ・再挑戦・手動終了で古い案内を次の状態へ持ち越さない。すべての物理イベントと音の処理は従来どおり行い、表示の優先度で得点や払い玉を捨てない。

狙い先の強調は入賞口の外側で行い、釘・球・液晶・操作ボタンを覆わない。画面効果軽減時は動きを止めても角枠・マーカー・文言を残す。元の盤面比率と衝突形状を維持し、参考作品の画像・動画・音声や新しい依存ライブラリは追加しない。

### 3.7 音の中断と再開

PR #34までの音処理では、ゲームの一時停止を解除してもブラウザの音声処理を再開していなかった。また、古い音ON要求が後から失敗すると、新しいONが成功済みでも内部設定をOFFへ戻していた。音声処理を代替した再現検査で、どちらも「音 ON」のまま次のイベントから音が生成されないことを確認した。

iOS Safariでは、タブ移動や画面OFFにより音声処理が`interrupted`となり、再開処理が必要になる。停止理由と再開方法は[MDNの音声状態の説明](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)、失敗時の契約は[再開処理の説明](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume)を根拠とする。端末で必ず同じ中断が起きるとは断定せず、実機での復帰と聴感は別に確認する。

- 音は初期OFFを維持し、明示的にONにした時だけ音声処理を生成する。ONで一時停止を解除する操作から、必要な場合だけ既存の音声処理を再開する。
- ON・OFF・停止・再開・破棄の順序を音処理内でも管理する。古い非同期処理の成功や失敗で、新しい選択や破棄済み状態を変更しない。
- 再開失敗はゲームへ伝えず、現在の要求の失敗だけを音ボタンへ反映する。ゲームの時計・入力・得点は音の再開を待たない。
- 停止中のイベント音はため込まず、復帰後に受け取ったイベントだけを鳴らす。OFF・停止・破棄では予約済みの音も止める。

既存の音色、音量、メロディ、表示、物理、抽選、時間、払い出しは変更しない。単体検査とブラウザ検査では音声処理を代替して再開要求・発音開始・停止を測る。この検査を、実際のスピーカー出力やiPhoneでの聴感確認と同一視しない。

### 3.8 外れの結果と次の期待への区切り

参考実装の`EffectsLayer.ts`は、全図柄の停止後に0.6秒の結果表示を挟み、`Game.ts`はその変動の完了を待って次の保留へ進む。DOPPANも外れを0.72秒表示するが、PR #35までの表示処理では、その間の副入賞などが外れの案内を消し、盤面の強調も中央入賞口へ戻っていた。結果から次のチャージ進捗へつながる情報が途切れていたため、既存の時間内で読み取れるようにする。

- 実際に外れを開示した`reveal`中だけ、液晶に静的な結果用の枠と停止マークを出す。中央入賞口へ注意を戻すのは、その結果表示が終わってからとする。
- 案内欄は「はずれ。チャージ n / 5。」とし、5回目の外れを開示した時にだけ「次は大当たり」を加える。液晶にも現在のチャージまたは保証を示す。未開示の保留や当落から予告を作らない。
- 同じ保留の結果表示中は、通常入賞・回収・発射でこの案内を消さない。一時停止や通常時間終了後の精算に入っても、その保留が同じ結果を表示中なら保持する。次の変動・待機・再挑戦・ゲーム結果へ移れば解除する。
- 色の違いだけに頼らず、文言と固定形状を残す。画面効果軽減時・音OFF時にも同じ情報を読めるようにし、球・釘・液晶内の文字・操作ボタンを覆わない。

外れの0.72秒、図柄停止と開示の時刻、PUSH受付、大当たり、保証の計算、得点、球、抽選、物理は変更しない。別の時計やアニメーション待ちを追加せず、既存のsession状態だけから表示する。自動検査では案内の保持・解除、実際の発射から外れへの到達、チャージとの一致、狭い画面と画面効果軽減時の表示を確認する。見やすさの証拠と、面白さの人手判断は区別する。

## 4. スコア損失、巻き返し、ランキング

発射の-10点は、入賞しない連射に明確な損失を返す。中央入賞、副入賞、大当たり、アタッカー入賞は、小達成、強い結果、ボーナス中の操作成果を別々に集計する。結果画面は最終得点に加え、発射数と発射減点、中央・副入賞の件数と合算得点、大当たりの件数と得点、アタッカー入賞の件数と得点、RUSH継続回数を表示する。中央入賞の件数は物理的な入賞を数え、保留満杯時などに受理されなかった入賞には得点を付けない。

巻き返しは、物理を秘密に易しくしたり得点を後から補正したりせず、外れ回数メーターと次回大当たり保証で実現する。保証の現在値`0 / 5`から`5 / 5`を常時読めるようにする。

新ルールの得点を既存の`doppan`ランキングへ送ってはならない。旧3球ルールと新90秒ルールでは得点機会と尺度が異なり、順位の比較が壊れる。`CLIENT_VERSION`は現在の取得RPCの集計条件ではないため、クライアント版だけを変更しても分離にならない。

2026-09-05のSupabase読取確認では、旧slug `doppan`の`games.is_active`は`false`であり、新ルール専用slugは登録されていない。現在の`submit_score_unverified`は対象ゲームの`is_active = true`を受理条件にするため、未登録slugへ新しい得点を送れない。一方、ゲーム行をアクティブにするとカメレオンJPの実験場へ表示され、今回の公開禁止と衝突する。

そのため、このDraft PRではゲーム行、schema、policy、database functionを変更せず、新ルールのスコア送信を行わない。結果画面のランキングdetailsは「新ルールのランキングは準備中」と示し、利用者が開いた時だけ旧3球ルールのTOP10を参考記録として読み取る。旧記録と今回の得点は比較できないことを同じdetails内へ明記し、旧slugへ新しい得点を暫定送信しない。

後続の第一候補は、ゲームの表示公開状態とスコア送信許可を別の状態として管理できるようにすることである。公開前の内部確認でも専用slugだけへ送信でき、実験場の一覧には出さない契約を、必要性、権限、表示条件、不正対策とともに別工程で設計する。分離を行わない場合は、公開承認後に`doppan-pachi-v1`などの専用slugを登録してアクティブにし、その時点から既存のゲーム終了時一回だけの送信を有効にする。

名前、共有、ランキングについては`d8fd997`時点の実装範囲を越える外部書き込みを追加しない。プレイ中の入賞、発射、保留、抽選、RUSH、seed、時間、操作履歴を外部へ送らない。

## 6. 実装境界

新しい実行経路は、旧`PinballWorld`を改造して旧試験と相互依存させず、新規`PachiWorld`と新規ルール状態を使う。旧`PinballWorld`、`GaSession`、`GrayboxRuntime`は参照履歴と旧試験のため残せるが、プレイヤー向け`main.ts`から接続しない。

責任を次のように分ける。

- `PachiWorld`: 複数球、発射、固定物、中央入賞、副入賞、アタッカー、アウトの各センサー、アタッカーの物理開閉、球回収、物理イベント

物理接触コールバック内で得点、保留、開閉を直接変更せず、有限のイベント列へ積み、固定ステップ後に一度だけ消費する。同じ球が同じ入賞口へ重複計上されないよう、球IDと入賞イベントIDを持つ。

## 7. 品質ゲート

旧C型や3球制で通過した試験を、新ゲームの合格として数えない。最初の必須縦切りは、テスト用のseedと実際の物理入力を使って開始から結果までを一続きで確認する。入力による発射で球数と得点が減り、保留に空きがある時の実球の中央入賞で得点、球、保留が増えなければならない。その保留が変動して通常停止またはリーチを経た後、大当たりなら得点と球を一度だけ加算し、アタッカーを物理的に開く。実球のアタッカー入賞で追加の得点と球を払い出し、二つの継続判定と最大3区間を越えずにRUSHを終える。最後に、90秒後の確定ticketを規則どおり精算して結果画面へ到達する。

最低限の自動検査は次とする。

- 同じseedと入力から同じ保留、図柄、RUSH結果になる
- 保留受理後に描画更新、PUSH、ポーズ、タブ非表示で当落が変わらない
- PUSHなし／受付／連打で同じ時刻に同じ結果と払い出しになり、PUSHイベントは一リーチにつき一度だけ。早押し・期限後・ポーズ・精算・手動終了でも再抽選や二重払い出しがない
- 発射強度はUI・読み上げ・左右キー・開始・resetで50/80/95と既定95の契約を共有し、通常操作から別の強度を選べない
- 保留はFIFO、最大4件で、満杯時と90秒後に5件目を作らず、中央入賞の50点と3球も加えない
- 保留に空きがある中央入賞だけがticket、50点、3球を一度に加える
- 中央払出なしの理由をHUDと盤面で表示し、左右の副入賞20点と2球は保留数に影響されない
- 5連続外れの次が必ず当たり、保証状態がsnapshotへ出る
- 保証ticketだけが仮の中央停止から再始動し、大当たり得点と30球を一度だけ受け取る
- 外れリーチが左右図柄の自然一致にだけ対応する
- 発射-10、中央入賞+50/+3球、副入賞+20/+2球、大当たり+1,500/+30球、アタッカー+100/+5球の内訳と結果が一致する
- 二つのRUSH判定が大当たり受理時に先決めされ、各1秒、1/2、合計最大3区間を守る
- BONUS中に通常保留を消化せず、区間、残り時間、継続判定を隠さない
- リーチ・PUSH・BONUSの重要な案内を通常入賞・回収で消さず、状態が変わったら古い案内を解除する
- 外れの既存0.72秒間は、結果と開示済みチャージを通常入賞・回収で消さない。5回目の外れの開示前に保証を示さず、次の変動・待機・ゲーム結果へ古い案内を持ち越さない
- 1秒の継続判定中は結果を画面・読み上げへ出さず、既存の継続・終了イベント後にだけ告知する
- 通常の中央入賞口、開放中の得点口、判定中の液晶を形と文言で区別し、320px幅と画面効果軽減時にも重なりや欠けがない
- 90秒後に通常発射と新規ticket受理が止まり、既存BONUSまたは精算中の最初の大当たりだけが終端BONUSを完走する
- 精算中の後続大当たりが得点と球を一度だけ受け取り、BONUSを重ねない
- 60秒上限と`manualFinish`が未表示の確定ticketを捨てず、再抽選せずに即時精算する
- 複数球を重複計上せず、回収後にbody、fixture、表示オブジェクトが残らない
- ポーズと画面非表示中に通常時間、変動、BONUS時間が勝手に進まない
- 乱数、時刻、得点に`NaN`、`Infinity`、範囲外の値が入らない
- 画面効果軽減と音なしでも保留、リーチ、当落、保証、RUSH終了を判別できる
- 音ONの中断復帰後に次のイベント音が生成され、古いON要求の失敗で最新の選択が変わらない。OFF・停止・破棄後は古い非同期処理から発音を再開しない
- ゲーム終了時以外にランキング送信が発生せず、旧slugへ新ルールの得点を送らない
- `npm run build`、静的検査、単体試験、物理試験、Chromium / WebKitの主要経路が成功する

現行の多数seed検査では、発射数、各入賞数、大当たり数、最終得点、初回入賞・大当たり時間、球の回収率、結果への到達を要約する。実効大当たり率とRUSH区間数の分布は、ランキング公開前の追加校正項目とする。得点とプレイヤー操作の結果である入賞数の相関が弱く、抽選seedだけで上位得点が決まる場合は、ランキング公開前に確率または得点配分を見直す。

自動検査の成功だけで、面白さ、期待感、惜しさ、逆転感、スマホ操作感、正式公開のゲートを通過扱いにしない。実装担当と別のSolがコードの独立レビューを行い、その後にユーザー本人がマージ、ゲート通過、正式公開を判断する。

## 8. 統合版の実装値と残る判断

`PachiSession`は`start`、`setPower`、`setFiring`、`setPaused`、`acknowledgePush`、`finish`、`step`、`snapshot`、`drainEvents`、`destroy`を公開する。`PachiWorld`は実球の発射・固定ステップ・入賞・開閉を管理し、表示はsnapshotを読む。

物理120Hz、同時球上限24、球寿命8秒、通常・BONUS共通の発射間隔0.20秒を型定数とする。得点は0から始まり負得点を許可する。90秒後の盤上球回収猶予は8秒、精算の絶対上限は60秒。残りの確定保留は上限到達時にも即時加点する。

発射球は右側の内外レールに沿って上昇し、上部の放出口から釘の間へ出る。中央・副入賞・アタッカーは下降中の進入だけを受け付け、発射直後に下側から吸い込む経路を作らない。発射ガイドの設定を物理と描画で共有する。

一ゲームのseedは`crypto.getRandomValues`で生成する。`debug=1&seed=<整数>`の場合だけ再現用seedを指定できる。seedやプレイ履歴を保存・送信しない。PUSH操作を追加しても確定結果は従来と同じ時刻で開示する。音はダウンロード不要の新規合成音で、初期状態はOFFとする。

再現校正は`npm run calibrate:pachi`で実行できる。既定では64seed×3段階（50/80/95）の192ゲームで、入賞・大当たり・得点・初回到達時間・回収率をまとめる。任意強度の指定は物理診断用に残す。この重い校正は通常のCI単体試験から分離する。検査の数値とブラウザ証跡は該当Draft PRへ記録する。

PR #33では192ゲームすべての終了と、3段階それぞれ64seedすべての中央入賞を確認した。表示だけの改善で抽選・物理・得点・球の処理を変えない場合は、変更がないことと既存検査の成功を確認し、多数seed校正を毎回の停止条件にはしない。

残る判断は、人手試遊での演出と操作感、確率・得点・払い玉の最終調整、新ルールのランキング送信許可と公開状態の分離である。1/5、外れ保証、80球、90秒、6秒などは試遊用の値であり、正式版の完成を意味しない。

この根本再設計のDraft実装開始に追加のユーザー確認は不要である。最新の指示が旧中心体験の見直しと参考作品の徹底参照を明示しているためである。ただし、本書の仮値、ランキング専用slug、ゲート通過、マージ、正式公開は自動的に承認済みとは扱わない。
