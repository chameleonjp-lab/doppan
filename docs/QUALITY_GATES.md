## 1. 目的

試験結果を見た後で「この程度なら合格」と基準を動かさないため、実施前に合否を固定する。

数値は永久不変ではない。変更する場合は、対象試験の結果を見る前に、理由と新しい値を意思決定記録へ残す。

データ、アカウント、外部通信、GitHub運用の基準は[データ非保存・GitHub運用方針](./DATA_AND_HOSTING_POLICY.md)を優先する。

## 2. 根拠の種類

| 種類 | 意味 | 扱い |
|---|---|---|
| 技術保証値 | 壁抜け、入力消失、重複得点、状態破損など | 原則として未達なら次へ進まない |
| 設計仮説値 | ショット成功率、得点比率、ゲーム時間など | 対象、難度、ルール仮説を見直す |
| プレイヤー観察値 | 初見理解、公平感、上達、満足など | 少人数では一般化せず、行動と理由を重視 |
| 制作予算 | 容量、作業回数、履歴上限など | 超過時は理由、影響、削減案を承認する |
| 安全運用値 | Actions権限、公開範囲、データ非保存、規約適合など | 未達なら公開・確認ページを停止する |

設計仮説値の未達は直ちに技術不良とは限らない。技術保証値、安全運用値の未達を、設計上の好みとして緩和しない。

---

## 3. 測定原則

- コミットSHA、盤面版、ルール版、環境名を記録
- 端末、OS、ブラウザ、向きを記録
- 同じ条件で複数回測る
- 平均だけでなく中央値、95パーセンタイル、最大値を見る
- 制作者試験、初見試遊、反復試遊を分ける
- 除外値へ理由を付ける
- 不合格後に基準を変えた場合、元の結果は不合格として残す
- Playwright WebKitをiPhone Safariの代わりにしない
- 各PRの端末確認は通過条件にせず、GA開始時とRCでまとめる
- 端末固有のP0またはP1が疑われる場合だけ、節目前でも対象を絞って確認する
- 乱数を使う物理試験ではseedを記録
- GitHub Pagesの未告知確認ページを非公開環境と表現しない
- 得点、履歴、回数、名前、識別子を試験のために永続保存しない
- 外部分析を試験導入してそのまま本番へ残さない

## 4. 不具合の重大度

| 等級 | 定義 | 公開判断 |
|---|---|---|
| P0 | 白画面、操作不能、重大権利問題、秘密情報公開、無断の個人情報収集・決済 | 1件でも公開不可 |
| P1 | 球消失、得点不整合、入力押しっぱなし、入力キュー消失、物理世界破損、状態消失、公開環境誤更新、禁止した記録保存・外部送信 | 1件でも次ゲート不可 |
| P2-Core | 中心操作、球視認性、主要ルール、状態遷移を大きく損なう | CCB以降0件必須 |
| P2-Peripheral | 設定や周辺機能を大きく損なうが回避可能 | 原則修正。残す場合は期限と承認記録 |
| P3 | 軽微な表示、文言、まれな違和感 | 公開後修正可 |

P0、P1、P2-Coreは例外承認しない。

# G1-A 技術基盤

## 5. 依存関係 — 技術保証値

次の正確な版を記録する。

- Node.js
- npm
- TypeScript
- `pixi.js`
- `planck`
- Vite
- Vitest
- Playwright Test
- ESLint
- typescript-eslint
- `@types/node`

合格条件:

- 旧`planck-js`を使わない
- `package-lock.json`を保存
- `packageManager`を記録
- `npm ci`で再現可能
- lock不整合時にCI失敗
- 直接依存と主要間接依存のライセンス記録
- 依存更新はゲーム機能と分離
- 認証、外部分析、広告、外部DB用の依存0件

## 6. 静的検査 — 技術保証値

- TypeScript型検査成功
- ESLint成功
- `any`を中心処理の逃げ道にしない
- 未処理Promiseを残さない
- 禁止依存方向を自動またはレビューで検出
- 接触コールバックからUI・音・物理変更を直接呼ばない
- 複数GameLoop開始経路を作らない
- 得点、履歴、回数、名前、識別子を保存層へ渡す参照0件
- ゲームルールからネットワーク通信を開始する参照0件

## 7. CI構成 — 安全運用値

### 7.1 ジョブ

pull requestと`main`で次が成功する。

- `npm ci`
- 型検査
- 静的検査
- 単体試験
- 本番形式ビルド
- 容量確認
- Playwright Chromium
- Playwright WebKit

### 7.2 ジョブ環境

- 別ジョブへ`node_modules`が自動共有される前提を置かない
- 複数ジョブなら各ジョブで`npm ci`
- npmキャッシュ利用可
- `dist`など必要な成果物だけArtifactで共有
- `node_modules`全体をArtifactへしない

### 7.3 権限と用途

- CI既定`contents: read`
- Pagesジョブだけ`pages: write`、`id-token: write`
- 不要な`contents: write`なし
- 第三者Actionを完全なコミットSHAへ固定
- 外部フォークへ秘密情報を渡さない
- `pull_request_target`で未信頼コードを実行しない
- Actionsを実行時API、定期集計、サーバーレスアプリ、配信網として使わない
- Actionsは開発、試験、ビルド、容量確認、配置だけに使用

## 8. GitHub Pages未告知確認枠 — 安全運用値

- GitHub Pagesを使用
- 完成前URLをREADME、SNS、公開サイトへ掲載しない
- 本番ルートに未完成ゲームを配置しない
- 本番ルートは開発中案内だけ
- 確認ページは信頼済み同一リポジトリブランチ一件だけ
- 外部フォークは公開しない
- `noindex,nofollow,noarchive`
- `robots.txt`
- 確認ページへ環境名、対象、コミットSHAを表示
- Pagesは公開URLであり秘密ではない旨を計画と画面で扱う
- `github-pages` Environmentにユーザー本人の必須reviewerと、bootstrap用`agent/g1a-technical-foundation`＋手動更新・cleanup用`main`だけのdeployment branch ruleを設定
- Environment保護確認後の`DEVELOPMENT_PREVIEW_ENABLED=true`がなければdeployをskip
- `main`への取り込みだけで正式版を公開しない
- 正式公開はG7と手動承認が必要

## 9. 非個人設定とデータ非保存 — 技術保証値

### 9.1 設定キー

- `development-preview`、`production`、`test`の設定キーを分ける
- ビルド環境名を表示
- 開発版の通常コードがproduction設定キーを読まない
- 開発版の通常コードがproduction設定キーを書かない
- 一時キーへ保存、読み戻し検査、正式キー反映
- 設定保存失敗でも起動・プレイ継続

許可キー:

```text
doppan:development-preview:settings:v1
doppan:production:settings:v1
doppan:test:settings:v1
```

### 9.2 設定内容

設定オブジェクトに含めてよいもの:

- 音
- 画面揺れ、点滅、粒子、軌跡の軽減
- 高コントラスト
- 初回案内

設定オブジェクトに含めてはいけないもの:

- 名前、メール、パスワード
- 利用者ID、端末ID、端末指紋
- 得点、最高得点、得点内訳
- 戦績、履歴、プレイ回数、日時
- 球数、盤面進行、倍率、コンボ

禁止フィールドを含む入力は保存拒否する。

### 9.3 ゲーム記録

- `localStorage`へ得点、最高得点、履歴、回数を書き込む経路0件
- `IndexedDB`へゲーム記録を書き込む経路0件
- Cookieへゲーム記録を書き込む経路0件
- URLへゲーム記録を永続状態として埋め込む経路0件
- 再読み込み後に進行中ゲームが復元されない
- 結果画面を閉じるか再挑戦すると今回の結果が初期化される
- アカウント、ログイン、名前入力画面0件
- 外部DB、分析、ランキングへの要求0件

同一オリジンのJavaScriptが技術的に別設定キーへアクセス可能であることを隠さない。信頼済みブランチ限定とG7後の確認ページ停止で防御する。

## 15. 入力イベントキュー — 技術保証値

- pointerId所有
- InputEventQueueとInputStateを分離
- sequenceId順で処理
- 同じ描画間隔内の押下・解放を消失させない
- 同じ物理ステップ前に押下・解放が来た場合、押下を一ステップ反映してから解放
- 追加する保持時間は最大一物理ステップ
- 未処理入力上限256件
- 257件目で黙って破棄せずP1安全停止
- 左右同時入力100回で押しっぱなし0件
- 不要な三本目100回で既存操作の誤解除0件
- pointercancel、lostpointercapture、blur、visibilitychange後の残留入力0件
- キーボードrepeat二重押下0件

## 16. 入力遅延

### 16.1 自動計測 — 技術保証値

- 入力イベントの受信時刻を物理反映まで保持する
- 入力から物理反映、入力から次の描画を別々に集計する
- 中央値、95パーセンタイル、最大値、件数を取得できる
- 計測標本は各256件以内に保つ
- 非有限値を診断へ混入させない
- リセットで前runの標本を残さない
- Chromium、WebKitで操作後に両方の標本が1件以上になる

### 16.2 端末上の入力から物理 — GA開始時へ繰り延べる確認値

| 端末 | 中央値 | 95パーセンタイル |
|---|---:|---:|
| iPhone 17 Pro | 50ms以下 | 90ms以下 |
| iPhone 11 Pro | 70ms以下 | 120ms以下 |

200ms超が反復する場合はP1。

### 16.3 端末上の入力から描画 — GA開始時へ繰り延べる確認値

| 端末 | 中央値 | 95パーセンタイル |
|---|---:|---:|
| iPhone 17 Pro | 70ms以下 | 120ms以下 |
| iPhone 11 Pro | 90ms以下 | 150ms以下 |

端末閾値は各PRの通過条件にしない。Playwrightでは液晶表示完了と端末負荷を再現できないため、GA開始時の計測と体感確認を併用する。

## 17. 固定時間 — 技術保証値

- 60Hz表示と120Hz表示でゲーム時間同一
- 非表示中の時間を一括消化0件
- 250ms以上の差を通常計算へ投入0件
- 60物理Hzは最大4ステップ/描画
- 120物理Hzは最大8ステップ/描画

- `runIntegrity`は結果表示と診断にだけ使用し、保存可否の判定には使用しない
