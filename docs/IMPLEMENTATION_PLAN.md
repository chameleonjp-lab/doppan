本書は、DOPPANをiPhoneのブラウザで安定して遊べる2Dピンボールとして実装する順序と範囲の正本である。

本書では次を扱う。

- 採用技術

- どの段階で何を作らないか

## 2. 技術構成

### 2.1 実行時

| 用途 | 固定構成 |
|---|---|
| 言語 | TypeScript |
| 描画 | `pixi.js` 8.19.0 |
| 物理 | `planck` 1.5.0。G1-Aは最小world/body/1ステップの読込確認のみ |
| 公開 | GitHub Pagesによる静的配信 |
| ゲーム処理 | プレイヤーのブラウザ内 |

旧パッケージ名`planck-js`は使わない。

正式版1.0では、認証、データベース、外部分析、ランキング用の実行時依存を追加しない。

| npm | 11.17.0 |

G1-Aでは`planck`をlockへ含め、最小の物理世界・動的body・1ステップだけの読込確認を行う。衝突、フリッパー、性能、継続可否はG1-Bで判定する。

## 3. 依存方向

```text
入力・UI
   ↓
入力キュー・ゲーム進行・状態
   ↓
ルール・ショット判定
   ↓
物理接続

物理状態 → 表示状態 → PixiJS
ゲームイベント → 表示・音・触覚
非個人設定 → UI初期値と表現設定
```

禁止:

- 物理からPixiJSを直接呼ぶ
- 得点ルールからHTMLを直接変更
- UIからPlanck.js物体を直接操作
- ルールへ音声ファイル名を書く
- 表示状態を得点やショット判定へ使う
- 接触コールバック内で物理世界を変更
- PixiJS Tickerと独自GameLoopを同時稼働
- 得点、履歴、回数、名前、識別子を保存層へ渡す
- ゲームルールから外部ネットワーク通信を開始する

## 4. 推奨ディレクトリ

```text
/
├─ docs/
├─ public/
│  └─ assets/
├─ src/
│  ├─ app/             # 起動、全体エラー、環境表示
│  ├─ game/            # 基本状態、球数、一回のゲーム進行
│  ├─ input/           # Pointer、Keyboard、イベントキュー、所有
│  ├─ loop/            # 単一GameLoop、固定時間、補間
│  ├─ physics/         # Planck接続、接触バッファ、物理命令
│  ├─ table/           # TableDefinition、検査、部品生成
│  ├─ runtime/         # TableRuntimeState、ゲート、経路
│  ├─ shots/           # 球別ショット状態機械
│  ├─ rules/           # 得点、倍率、球間進行、モード
│  ├─ rendering/       # PixiJS、表示同期、WebGL復旧
│  ├─ audio/           # 音イベント、同時再生制限
│  ├─ haptics/         # 任意の短い触覚
│  ├─ storage/         # 非個人設定だけ。ゲーム記録は禁止
│  ├─ diagnostics/     # 性能、有限履歴、試遊レポート
│  └─ ui/              # タイトル、ポーズ、結果、設定
├─ tests/
│  ├─ unit/
│  ├─ physics/
│  ├─ fixtures/
│  └─ e2e/
└─ .github/workflows/
```

初期段階で空ファイルを大量に作らない。G1-A、G1-Bで必要な責任だけを分ける。

正式版1.0では、外部テレメトリー、認証、ランキング、データベース接続を作らない。

## 7. G1-B: ピンボール技術試作

### 7.1 目的

G1-Aで完成した基盤上に、品質ゲートを実際に測れる最小のピンボールを作る。

### 7.2 実装範囲

- Planck.js world
- 左右フリッパー2本
- 球1個
- 外周壁
- 発射装置
- 発射レーン
- 発射強度確認用3区画
- 安全ショット用の単純通路1本
- Pointer Events二本指
- キーボード
- InputEventQueue
- InputState、InputOwnership
- 60Hz / 120Hz固定時間比較
- 用途別接触イベント
- PhysicsCommandQueue
- ショット状態機械
- `baseState`と`suspensionState`
- pendingTerminalEvents
- 安全位置と回復
- 入力・物理・描画遅延表示
- 資源数表示
- 試験用診断出力
- 一回のゲーム状態をメモリだけで保持する境界試験

### 7.3 発射

G1-Bでは、ばねの完全再現より再現性を優先する。

- 引いて離す
- 長押しして離す

を比較する。

強度は決定的な初速またはimpulseへ変換し、乱数を加えない。

攻略価値と初見理解が不足する場合は固定発射へ変更する。

### 7.4 球受け・保持

中心技能として残すかを検証する。

- 面白さを増す → 継続
- 経験者だけが使う → 上級技能
- 初心者を妨げる → 初回案内から外す
- 物理全体を不自然にする → 作品約束から外す

### 7.5 データ境界

G1-Bの得点、球数、進行、診断はメモリだけで管理する。

必須:

- ページ再読み込みで一回のゲーム状態が復元されない
- `localStorage`、`IndexedDB`、Cookieへ得点、球数、進行を書かない
- 外部へ得点、開始、終了を送信しない
- 設定保存部品をゲーム状態から参照しない
- 診断レポートは自動送信しない

### 7.6 完了条件

- 全技術保証値を通過
- 設計仮説値の結果を記録
- Planck.js継続または見直しを決定
- 60Hzまたは120Hzを決定
- 発射方式の技術候補を決定し、端末上の操作感はGAで確定
- 球受け・保持の技術的成立性を記録し、面白さの位置付けはGAで確定
- ゲーム記録の永続保存と外部送信がないことを確認
- `PRODUCTION_STATUS.md`を更新

端末固有の重大不具合が疑われない限り、G1-Bの各PRで実機確認を要求しない。

## 11. 状態

本体状態と一時停止理由を分ける。

```text
baseState
suspensionState
pendingTerminalEvents
```

発射待ち中に画面非表示になった場合、復帰後も発射待ちへ戻る。

球落下と画面非表示が同時の場合、球終了を保留して復帰後に完了する。

重大エラーは通常復帰せず、安全停止へ移る。

一回のゲーム終了、再挑戦、再読み込みでは、RuleState、TableRuntimeState、球別ショット状態、入力、診断の一時値を引き継がない。

## 12. 非個人設定とゲーム記録の禁止

### 12.1 許可する設定

- 音の有無と音量
- 点滅、粒子、揺れ、軌跡の軽減
- 高コントラスト
- 初回案内の表示設定

環境別キー:

```text
doppan:development-preview:settings:v1
doppan:production:settings:v1
doppan:test:settings:v1
```

更新:

1. 一時キーへ書く
2. 読み戻す
3. 型と値を検査
4. 正式キーへ反映
5. 一時キーを削除

設定保存失敗でもプレイを続ける。開発版は通常処理で本番設定キーを使わない。

### 12.2 保存禁止

設定オブジェクトへ次を追加しない。

- 名前、メール、アカウント情報
- 利用者ID、端末ID、端末指紋
- 得点、最高得点、得点内訳
- 戦績、履歴、プレイ回数、日時
- 球数、盤面進行、倍率、コンボ
- リプレイ、ゴースト

ゲーム状態はメモリだけで管理する。`localStorage`、`IndexedDB`、Cookie、URLパラメーターへゲーム記録を書かない。

既存の`SaveStorage<T>`はそのままゲーム記録へ転用しない。設定専用の型と名称へ狭め、禁止フィールドを試験する。

## 14. 性能と容量

固定した初期目標:

- JavaScriptとCSS: gzip後600KB以内
- 初回画像: 1.5MB以内
- 初回音声: 1.5MB以内
- 初回転送合計: 3MB以内
- 遅延素材込み: 10MB以内

負荷削減順:

1. 粒子
2. 影
3. 発光解像度
4. 軌跡点数
5. UI更新頻度
6. 画像解像度

物理計算回数を最初に下げない。

時間切り捨てが反復したゲームは、結果画面へ公正性の注意を表示できる。ゲーム記録は永続化しないため、自己最高の更新処理は存在しない。

運用想定:

- 1日100人
- 1日200プレイ
- 毎回10MBを読み直す厳しい条件で約60GB／月
- 内部停止線は月70GB見積もり、GitHub警告、HTTP 429の反復

## 15. アクセシビリティ

正式版までに次を満たす。

- 音なしでも主要状態を理解
- 点滅、粒子、揺れを軽減
- `prefers-reduced-motion`を初期設定へ反映
- 一秒に3回を超える強い点滅を作らない
- 高コントラスト
- 色だけに依存しない
- 主要操作対象は最低24×24 CSSピクセル
- 主ボタンは可能な範囲で44×44 CSSピクセル前後
- PCではキーボードだけで開始から終了

軽減設定でもクライマックスの成否が分かることを確認する。

## 18. GitHub運用

- `main`へ直接実装しない
- 一つの確認可能な成果物につき一つのDraft PR
- G1-AとG1-Bを分ける
- 仕様変更と正本文書更新を同じPRへ含める
- 自動検査失敗で取り込まない
- PR本文へ自動ゲート、端末確認へ残す項目、残る問題を記載
- 確認URLは外部へ転載しない
- `main`マージを正式公開へ直結させない
- RCでは新機能を入れない
- Actionsは開発、試験、ビルド、配置だけに使う
- Actionsを実行時API、定期集計、配信網として使わない

推奨ブランチ:

```text
agent/g1a-technical-foundation
agent/g1b-physics-prototype
agent/core-experience-and-shot-map
agent/graybox-alpha
agent/vertical-slice
agent/content-complete
agent/release-candidate
```
