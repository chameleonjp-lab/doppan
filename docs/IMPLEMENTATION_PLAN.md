## 2. 技術構成

### 2.1 言語

TypeScriptを使用する。

中心処理では次を型で区別する。

- ゲーム状態
- 球ID
- 部品ID
- ショットID
- 入力所有者
- 物理イベント
- 得点イベント
- 盤面版、ルール版、保存版、クライアント版

外部入力は`unknown`として受け、検査後に使う。中心処理で`any`を逃げ道にしない。

### 2.2 描画

PixiJSを使用し、本番描画経路はWebGLとする。

- Canvasを完全代替として保証しない
- WebGPUは正式版1.0で使わない
- 正確な版をlockファイルで固定
- `devicePixelRatio`は初期上限2
- WebGL初期化失敗時は非対応案内
- コンテキスト喪失と復旧を試験
- 復旧中は物理を自動ポーズ
- 復旧失敗時は再読み込み案内

### 2.3 物理

Planck.jsをTPの第一候補とする。

対象:

- 球
- 壁、レール
- フリッパー
- 発射装置
- バンパー、スリングショット
- ゲート、センサー、落下判定

球は高速物体として扱う。採用版はlockファイルで固定する。

### 2.4 開発と公開

- Vite
- Vitest
- GitHub Actions
- GitHub Pages
- Node.jsの正確な版をワークフローで固定
- lock準拠で依存取得
- GitHub Pagesの基底パスを明示

実行時依存を追加する場合、理由、代替、容量、ライセンス、iPhoneへの影響をPRへ記載する。

## 3. 依存方向

```text
入力・UI
   ↓
ゲーム進行
   ↓
ルール・ショット判定
   ↓
物理接続

物理状態 → 描画同期 → PixiJS
ゲームイベント → 表示・音・触覚
```

禁止:

- 物理からPixiJSを直接呼ぶ
- 得点ルールからHTMLを直接変更
- UIからPlanck.js物体を直接操作
- ルールへ音声ファイル名を書く
- 描画状態を得点判定へ使う

## 5. 座標と時間

### 5.1 盤面座標

CSSピクセルから分離した共通単位を使う。

端末差で変えないもの:

- 重力
- 球速、球半径
- 壁厚
- フリッパー長
- センサー位置

### 5.2 固定時間刻み

TPで次を比較する。

- 1秒60回
- 1秒120回

初期方式:

- 時間蓄積
- 描画位置は直前と現在の物理状態から補間
- 1描画で最大4物理ステップ
- 非表示中の経過時間は破棄
- 250ミリ秒超の差を通常計算へ渡さない
- 復帰時は全入力解除し、自動ポーズで表示

### 5.3 数値設定

設定ファイルへ集約する。

- 重力
- 球の半径、質量、反発、摩擦
- 球速上限
- フリッパー角度、速度、トルク
- 発射強度
- バンパー反発
- ボールセーブ
- 得点待ち時間
- 得点

変更理由はPRまたは[意思決定記録](./DECISION_LOG.md)へ残す。

## 6. 入力所有

### 6.1 基本

`pointerId`を押し始めた操作へ固定する。

```text
pointerId 12 → 左フリッパー
pointerId 18 → 右フリッパー
pointerId 24 → 発射装置
```

指が別領域へ移動しても、`pointerup`まで別操作へ変更しない。

### 6.2 所有規則

- 左右フリッパーは各1本の指だけが所有
- 発射装置は発射待ちだけ所有可能
- 同じ操作への二本目は無視
- 未割り当ての不要な指は無視
- ポーズは独立HTMLボタン
- `setPointerCapture`を明示使用

### 6.3 全解除条件

- `pointerup`
- `pointercancel`
- `lostpointercapture`
- `visibilitychange`
- `window.blur`
- ポーズ
- 状態変更
- 球終了
- 結果画面
- 例外時の安全停止

全解除は一つの関数へ集約する。

### 6.4 ページ操作

- ゲーム操作面だけ`touch-action: none`
- 設定、説明、結果画面のスクロールと拡大を一律禁止しない
- 安全領域とホームインジケータを避ける
- 押下状態は指の下だけでなく盤面上でも分かる

## 7. 物理実装

### 7.1 球

持つ情報:

- ID
- 位置、速度、回転
- 所属状態
- 最後の安全位置
- 最後の有効移動時刻
- 再配置理由

正式版1.0は同時一球とする。

### 7.2 フリッパー

設定:

- 休止角度、最大角度
- 上昇速度、復帰速度
- 最大トルク
- 入力状態
- 左右区分

確認:

- 根元と先端で球筋が変わる
- 連打で角度が壊れない
- 球が内部へ潜り込まない
- 球を受けて狙い直す余地がある

球の保持を正式版必須に残すかは、[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)の分岐で決める。

### 7.3 正常な保持と異常停止

正常候補:

- フリッパー近辺
- フリッパー入力中
- 低球速
- 継続接触
- 盤面内

異常候補:

- 到達不能
- 部品に挟まる
- 正常条件を満たさない低速継続
- 非有限値
- 盤面外で残る

正常保持中は回収しない。

### 7.4 再配置

1. 異常を記録
2. 正常保持でないことを確認
3. 最後の安全位置を確認
4. 低速で再配置
5. 同じ場所で再発したら球終了
6. システム起因なら残り球を減らさない

### 7.5 Planck.js見直し

2調整サイクル後も次が残る場合、盤面制作を止める。

- ショット再現性未達
- 球を受ける操作が不安定
- 高速衝突で球抜け
- 120回計算でも接触不整合
- iPhone 11 Proで性能未達
- 大量の個別補正が必要

見直し順:

1. 関節と接触形状
2. 限定的な接触補助
3. 球速上限と盤面形状
4. 物理方式またはエンジン
5. 作品約束から保持を外す判断

## 8. 発射装置

TPで比較する。

- 引いて離す
- 長押しして離す

採用条件:

- 盤面を隠しすぎない
- 最小、中間、最大を再現できる
- フリッパーと誤入力しない
- 基本スキルショットへ使える
- 初見で理解できる

攻略へ使えない場合は固定発射へ簡略化する。

## 9. 盤面データとショット判定

### 9.1 盤面データ

- 盤面サイズ
- 外周、レール
- フリッパー、発射レーン
- バンパー、スリングショット
- レーン、目標
- アウトレーン、落下口
- センサー
- ショット入口、出口
- 部品ID、ショットID
- 得点、進行

### 9.2 読み込み拒否

- ID重複
- 必須座標不足
- 0以下の大きさ
- 未対応部品
- 盤面外の重要部品
- 存在しない参照
- 落下口なし
- 初期球が部品内部
- 不正フリッパー角度
- 重複ショットID

### 9.3 ショット成功

一つのセンサーだけで成功にしない。

必要に応じて使う。

- 入口通過
- 進入方向
- 出口通過
- 通過順序
- 最低速度
- 同一球内の重複防止

### 9.4 版

- `tableVersion`
- `rulesVersion`
- `clientVersion`
- `saveVersion`

## 10. ゲーム状態

最低限:

- 起動中
- タイトル
- 初回案内
- 発射待ち
- プレイ中
- 自動ポーズ、手動ポーズ
- ボールセーブ再発射
- 球終了処理
- 次球準備
- ゲーム終了
- 結果
- 練習

状態ごとに入力、物理、得点、保存、音の許可を定義する。

球終了時:

- 恒久進行維持
- コンボと一時状態終了
- 全入力解除
- 短い球結果
- 次球準備

再読み込み時:

- 進行中ゲームを復元しない
- ランキング対象にしない

## 11. 表示・音・表現

表現の正本は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)とする。

技術上の必須:

- 球を最優先で表示
- 高速時の短い軌跡
- 強い発光でも球を隠さない
- 色だけに依存しない目標
- 音なしでも情報が欠けない
- 触覚なしでも正常動作

WebGL復旧対象:

- コンテキスト喪失
- アプリ切り替え
- 画面ロック
- 長時間非表示
- メモリ圧迫後

音:

- 最初の明示操作後に開始
- 復帰後に再開できなければ再操作を求める
- 同じ音の同時再生を制限
- 音イベント名で管理

## 12. 保存と共有

保存:

- 最高得点
- 主要得点内訳の自己最高
- 音・画面効果・高コントラスト・軌跡
- 初回案内
- 保存版

方針:

- 永久保持を保証しない
- 保存失敗でも続行
- プライベートブラウズ試験
- 読み込み不能時は安全な初期値
- 進行中ゲームは保存しない

共有:

1. Web Share API
2. 結果テキストをクリップボードへコピー
3. URLと結果文を画面表示

共有失敗をゲーム失敗にしない。

## 13. 試遊レポート生成

GAまでに、外部送信なしで端末内レポートを作る。

出力:

- 読みやすいテキスト
- 必要に応じて`playtest-report.json`

含める:

- コミットSHA、各版
- 端末、OS、ブラウザ、画面サイズ
- 各球の時間、落下場所
- ショット試行・成功
- 得点内訳
- 球を受けた回数、保持候補回数
- 入力解除、ポインター異常
- フレーム時間要約
- WebGL、音声、未処理エラー

含めない:

- 氏名
- 連絡先
- 永続的な端末識別子
- 自動送信

利用者が内容を確認してコピーする。

## 16. 性能と容量

暫定目標:

- JavaScriptとCSS: gzip後600KB以内
- 初回画像: 1.5MB以内
- 初回音声: 1.5MB以内
- 初回転送合計: 3MB以内
- 遅延素材込み総容量: 10MB以内

負荷削減順:

1. 粒子
2. 影
3. 発光解像度
4. 軌跡点数
5. UI更新頻度
6. 画像解像度

物理計算回数を最初に下げない。
