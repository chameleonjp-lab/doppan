## 1. この計画書の目的

DOPPANを、iPhoneのブラウザで安定して遊べる2Dピンボールとして実装する。

本書は、次を曖昧にしない。

- 入力をどのように所有・解除するか
- 物理時間と描画時間をどう分けるか
- WebGLが失われた時にどう復旧するか
- 球の保持と異常停止をどう区別するか
- 球間の進行をどう扱うか
- 保存が消える可能性をどう扱うか
- 対応端末と非対応条件
- Planck.jsで目標品質が出ない時にいつ見直すか
- どの段階を公開可能と呼ぶか

判断の優先順位は上位計画書に従う。

## 2. 技術構成

### 2.1 言語

TypeScriptを使用する。

中心処理では次を型で区別する。

- ゲーム状態
- 球ID
- 盤面部品ID
- ショットID
- 入力所有者
- 物理イベント
- 得点イベント
- 盤面版
- ルール版
- 保存データ版

外部入力は`unknown`として受け、検査後に使う。中心処理で`any`を逃げ道にしない。

### 2.2 描画

PixiJSを使用し、本番描画経路はWebGLとする。

- Canvas描画を自動的な完全代替として保証しない
- WebGPUは正式版1.0で使用しない
- PixiJSの正確な版をlockファイルで固定する
- `devicePixelRatio`は初期値として最大2へ制限し、実機計測で下げる
- WebGL初期化失敗時は、非対応案内を表示する
- WebGLコンテキスト喪失と復旧を試験する
- 描画復旧に失敗した場合は、安全にゲームを停止し、再読み込みを案内する

### 2.3 物理

Planck.jsを第一候補とする。

- 球
- 壁
- レール
- フリッパー
- 発射装置
- バンパー
- スリングショット
- ゲート
- センサー
- 落下判定

球は高速物体として扱う。採用版はlockファイルで固定する。

### 2.4 開発と配信

- Vite
- Vitest
- GitHub Actions
- GitHub Pages
- Node.jsはワークフローで正確な版を固定
- `npm ci`または同等のlock準拠取得
- GitHub Pagesの基底パスを明示

新しい実行時依存関係を追加する場合は、理由、代替案、容量、ライセンス、iPhoneへの影響をPRへ記載する。

## 3. 依存方向

```text
入力・UI
   ↓
ゲーム進行
   ↓
ルール・ショット判定
   ↓
物理接続

物理状態 → 描画同期 → PixiJS
ゲームイベント → 表示・音・触覚
```

禁止する参照:

- 物理処理からPixiJSを直接呼ぶ
- 得点ルールからHTMLを直接変更する
- UIからPlanck.jsの物体を直接動かす
- 盤面ルールへ音声ファイル名を書く
- 描画状態を得点判定へ使う

## 5. 座標と時間

### 5.1 盤面座標

盤面座標はCSSピクセルから分離する。

表示時だけ画面へ変換し、端末差で次が変わらないようにする。

- 重力
- 球速
- 球の半径
- 壁厚
- フリッパー長
- ショットセンサー

### 5.2 固定時間刻み

初期比較は次の二案とする。

- 1秒60回
- 1秒120回

描画とは分離し、描画位置は直前と現在の物理状態から補間する。

推奨初期実装:

- 時間蓄積方式
- 1描画で進める物理ステップは最大4回
- 画面非表示中の経過時間は破棄
- 250ミリ秒を超える大きな時間差は通常計算へ渡さない
- 復帰時は全入力解除後に一時停止状態で表示する

### 5.3 数値設定

次を設定ファイルへ集約する。

- 重力
- 球の半径、質量、反発、摩擦
- 球速上限
- フリッパー角度、速度、トルク
- 発射強度
- バンパー反発
- ボールセーブ
- 得点待ち時間
- 各得点

変更理由を[意思決定記録](./DECISION_LOG.md)またはPRへ残す。

## 6. 入力所有モデル

### 6.1 基本方針

指が触れた瞬間に、その`pointerId`を一つの操作へ割り当てる。

```text
pointerId 12 → 左フリッパー
pointerId 18 → 右フリッパー
pointerId 24 → 発射装置
```

押し始めた操作は`pointerup`まで維持し、指が別領域へ動いても途中で別操作へ変更しない。

### 6.2 所有規則

- 左フリッパーは同時に一つの指だけが所有
- 右フリッパーも同様
- 発射装置は発射待ち状態だけ所有可能
- 同じ領域へ二本目の指が入った場合は無視
- 未割り当ての三本目以降の指は無視
- ポーズは専用HTMLボタンで扱い、盤面入力と同時に発動させない
- `setPointerCapture`を明示的に使う
- 指が領域外へ移動しても、所有は解放まで維持する

### 6.3 解除条件

次のすべてで対応する入力を解除する。

- `pointerup`
- `pointercancel`
- `lostpointercapture`
- `visibilitychange`
- `window.blur`
- ゲーム状態の変更
- ポーズ
- 球終了
- 結果画面
- 例外発生時の安全停止

全解除処理を一つの関数へ集約する。

### 6.4 `touch-action`

- ゲーム盤面の操作面だけ`touch-action: none`
- 設定、説明、結果画面まで一律に拡大・スクロール不能にしない
- 主要操作領域は安全領域とホームインジケータを避ける
- 押下状態は指の下だけでなく、盤面上のフリッパー反応でも確認できる

## 7. 物理実装

### 7.1 球

球が持つ情報:

- 一意なID
- 位置、速度、回転
- 所属状態
- 最後に安全だった位置
- 最後に意味のある移動をした時刻
- 最後の再配置理由

正式版1.0は同時に一球だけとする。

### 7.2 フリッパー

- 回転関節
- 休止角度
- 最大角度
- 上昇速度
- 復帰速度
- 最大トルク
- 入力状態
- 左右区分

品質条件:

- 根元と先端で球筋が変わる
- 1.5秒以上の短時間保持が可能
- 保持から安全ショットへ狙い直せる
- 連打で角度が壊れない
- 球が内部へ潜り込まない

### 7.3 正常保持と異常停止

正常保持:

- フリッパー近辺
- フリッパー入力中
- 低球速
- 継続接触
- 盤面内

異常停止:

- 到達不能な場所
- 壁と部品に挟まる
- 正常保持条件を満たさず低速が長時間続く
- 数値が非有限
- 盤面外で残る

正常保持中は自動回収しない。

### 7.4 安全な再配置

1. 異常を記録
2. 正常保持でないことを確認
3. 最後の安全位置を確認
4. 低速で再配置
5. 同じ場所で再発した場合は球終了
6. システム起因の回収では残り球を減らさない

### 7.5 Planck.jsの見直し条件

次のいずれかが、調整2サイクル後も解消しない場合は、盤面制作を止めて方式を見直す。

- 目標ショットの再現性が品質ゲート未達
- フリッパー保持が安定しない
- 高速衝突で球抜けが残る
- 1秒120回でも重大な接触不整合が残る
- iPhone 11 Proで性能条件を満たさない
- 補助力を大量に追加しないと操作が成立しない

見直し順:

1. 関節と接触形状
2. フリッパー接触時の限定補助
3. 球速上限と盤面形状
4. 物理方式またはエンジン

## 8. 発射装置

グレー版アルファから、発射強度を攻略へ使う。

比較する操作:

- 引いて離す
- 長押しして離す

採用条件:

- 指で盤面を隠しすぎない
- 最小・中間・最大を再現できる
- フリッパーと誤入力しない
- 基本スキルショットへ使える
- 初見でも発射方法を理解できる

発射強度を攻略へ使えない場合は、固定発射へ簡略化する。

## 9. 盤面データとショット判定

### 9.1 盤面データ

- 盤面サイズ
- 外周
- フリッパー
- 発射レーン
- バンパー
- スリングショット
- レーン
- 目標
- アウトレーン
- 中央落下口
- センサー
- ショット入口と出口
- 部品IDとショットID
- 得点と進行

### 9.2 読み込み時の拒否

- ID重複
- 必須座標不足
- 0以下の大きさ
- 未対応部品
- 盤面外の重要部品
- 存在しない参照
- 落下口なし
- 初期球が部品内部
- 不正なフリッパー角度
- 重複ショットID

### 9.3 ショット判定

一つのセンサーだけで成功としない。

必要に応じて組み合わせる。

- 入口通過
- 進入方向
- 出口通過
- 通過順序
- 最低速度
- 同一球内の重複防止

### 9.4 版管理

- `tableVersion`
- `rulesVersion`
- `clientVersion`
- `saveVersion`

公開記録、診断情報、将来のランキングへ含める。

## 10. ゲーム状態

最低限の状態:

- 起動中
- タイトル
- 初回案内
- 発射待ち
- プレイ中
- 自動ポーズ
- 手動ポーズ
- ボールセーブ再発射
- 球終了処理
- 次球準備
- ゲーム終了
- 結果
- 練習

状態ごとに、入力、物理、得点、保存、音を許可するか明示する。

球終了時:

- 恒久進行を維持
- コンボと一時モードを終了
- 全入力解除
- 短い球結果を表示
- 次球準備

再読み込み時:

- 進行中ゲームを復元しない
- 中断記録としてもランキング送信しない

## 11. 表示

### 11.1 球の視認性

- 背景と十分な明度差
- 輪郭またはハイライト
- 高速時の短い軌跡
- 強い発光中も球を隠さない
- 軌跡を無効化可能
- 色だけに依存しない

### 11.2 目標表示

- 形
- 模様
- 短い文字
- 矢印
- 明るさ
- 点灯順

常時すべてを点滅させない。

### 11.3 WebGL復旧

試験対象:

- コンテキスト喪失
- アプリ切り替え
- 画面ロック
- 長時間非表示
- メモリ圧迫後の復帰

復旧中はゲームを自動ポーズし、物理を進めない。

---

## 12. 音と触覚

- 音は最初の明示操作後に開始
- アプリ復帰後に再開できない場合は、再度操作を求める
- 同じ音の同時再生数を制限
- 接触速度で音量と高さを小さく変える
- 音なしでも情報が欠けない
- 触覚は正式版1.0必須にしない
- 触覚が利用できなくても正常動作

音声イベント名で管理し、ファイル名をルールへ散らさない。

---

## 13. 保存

正式版1.0で保存するもの:

- 最高得点
- 主要得点内訳の自己最高
- 音設定
- 画面効果設定
- 高コントラスト
- 球の軌跡
- 初回案内
- 保存データ版

方針:

- ブラウザ保存は永久保持を保証しない
- 保存失敗でもプレイを続ける
- 容量不足や利用者削除に対応
- プライベートブラウズで試験
- 読み込み不能時は安全な初期値へ移行
- 進行中ゲームは保存しない
- 将来の書き出しやオンライン保存は拡張扱い

---

## 14. 結果共有

Web Share APIが利用可能な場合だけ使う。

代替順:

1. 共有
2. 結果テキストをクリップボードへコピー
3. URLと結果文を画面へ表示

共有失敗をゲーム失敗として扱わない。結果画像生成は正式版1.0の必須外とする。

## 15. 対応端末

### 15.1 Tier 1: 公開判断に使う実機

- iPhone 17 Pro
- iPhone 11 Pro
- iPad Pro 2018
- デスクトップ相当Chromeの自動確認

### 15.2 Tier 2: 最善努力

- CSS表示幅320〜430
- リリース時のiOS Safari現行版と直近世代
- Android Chrome
- 外部キーボード

Tier 2は、実機未確認の場合に動作保証を表明しない。

### 15.3 画面方向

正式版1.0は縦画面を正式対応とする。

横画面では:

- 自動回転で物理座標を変更しない
- 自動ポーズ
- 縦画面を推奨する案内
- 継続する場合も盤面を縮小表示

### 15.4 非対応条件

- WebGLが初期化できない
- JavaScript無効
- 必要なポインター入力が利用できない
- 極端に小さい表示領域

非対応時は白画面にせず、理由を表示する。

## 16. 外部データ収集

正式版1.0では、利用状況を外部送信しない。

開発用に保持できるもの:

- 直近の入力
- 直近の状態遷移
- 接触イベント
- ショット試行と成功
- 描画速度
- 物理遅れ
- 版情報

これらは端末内の一時情報とし、利用者が内容を確認してコピーする方式を優先する。

外部送信を追加する場合は、別文書で次を決める。

- 収集項目
- 目的
- 同意
- 保存期間
- 削除
- 個人情報との結び付き
- プライバシー表示

## 17. 性能と容量

暫定予算:

- 初回JavaScriptとCSS: gzip後600KB以内を目標
- 初回画像: 1.5MB以内
- 初回音声: 1.5MB以内
- 初回転送合計: 3MB以内を目標
- 遅延読み込みを含む総素材: 10MB以内を目標
- 実行時依存関係: PixiJS、Planck.jsを中心とし、追加は個別承認

予算を超えた場合は、縦切り版で理由と実機影響を確認する。

負荷削減順:

1. 粒子
2. 影
3. 発光解像度
4. 軌跡点数
5. UI更新頻度
6. 画像解像度

物理計算回数を最初に下げない。
