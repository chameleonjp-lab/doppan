## 1. 今回の目的

G2の仮図形を、開始から結果表示まで通して遊べる3球の一回のゲームへ接続する。

今回の自動検証は、ゲームのライフサイクル、球をまたぐ進行、結果、再挑戦、データ非保存の境界を確認する。初見で面白いか、狙いが伝わるか、端末で気持ちよく操作できるかは自動合格に含めない。

## 2. 実装範囲

- 3球制の`GameLifetime`
- 球開始、球終了、次球の発射待ち、3球目終了後の結果状態
- 得点とショット進行の球間保持
- コンボの球終了時リセット
- 「新しいゲーム」による得点、進行、球数、結果、診断レポートの初期化
- ゲーム開始、球開始、ショット成功、球終了、ゲーム終了の有限レポート
- 画面上の球数、残り球数、フェーズ、結果表示
- 明示操作による試遊レポートの表示・コピー

本番素材、正式ロゴ、音楽、ランキング、アカウント、認証、Supabase、外部分析、外部通信は含めない。

## 3. データ境界

- 得点、進行、コンボ、診断、試遊レポートはブラウザのメモリ内だけで保持する
- `localStorage`、`IndexedDB`、Cookie、URL、外部サービスへゲーム記録を書かない
- レポートは自動送信せず、プレイヤーがボタンを押した時だけ画面表示またはクリップボードへのコピーを試みる
- レポートへプレイヤー名、アカウント、永続的識別子、日時の個人記録を入れない
- ページ公開、確認URLの外部案内、正式公開はこのPRの範囲外とする

## 4. 自動確認項目

PR #11 / GitHub Actions Run #24では次を確認した。

1. TypeScript、ESLint、依存境界が通る
2. 既存のG1-B / G2の入力、物理、ショット、ゲート、再初期化テストが通る
3. 3球を順に終了させても、得点と進行が球間で保持される
4. 球終了ごとにコンボが解除され、3球目終了後に結果が固定される
5. 結果状態で追加発射を受け付けず、「新しいゲーム」で再び1球目へ戻る
6. レポートにゲーム開始からゲーム終了までのイベントが含まれ、件数が上限内に収まる
7. PlaywrightのChromium / WebKitで起動、再読込、入力、レポート、非保存境界を確認する
8. 本番ビルドとgzip容量が既存停止線を超えない

### 4.1 Pages配信の追加確認

過去の確認では、未変換の`/src/main.ts`が直接配信され、画面が「初期化中」のまま停止した。また、Pages Sourceがlegacy / mainへ戻った時期には、ルートがゲーム画面を返し、`/_preview/current/`と`robots.txt`が404だった。

この問題は、Pages SourceをGitHub Actionsへ設定し、Repository variable `DEVELOPMENT_PREVIEW_ENABLED=true`でmainを手動実行したことで解消した。2026-08-15のDevelopment preview Run #16（main SHA `5f5b72bf7ceb0a491865b2adeb6ae6d425fd0482`）はverify / publishとも成功した。

実URLの確認結果:

- ルート: `DOPPAN — 公開前案内`
- `/_preview/current/`: `DOPPAN — つなぎ直す`
- `robots.txt`: `Disallow: /`
- Pages deployment: `5919371962`

Pages配信確認は完了したが、これは正式公開、初見理解、人手試遊の合格を意味しない。

### 4.2 GA理解性パスの統合候補

PR #12で検証した理解性パスを、PR #13で確定したPages配信境界を保った統合候補へ取り込む。

- 内部識別子を「左の安全ショット」などのプレイヤー向け表示へ変換する
- 黄色の目標と、成功後に戻り道が変わることを短く案内する
- 試遊レポートの表示・コピー状態を実際の結果と一致させる
- 物理、入力、ショット順、3球制、得点、保存、外部通信は変更しない
- 自動ゲートの成功は初見理解、操作感、面白さの合格を意味しない

## 4.3 プレイヤー画面・操作面の対応

ゲームデザイン責任者レビューで、技術診断が通常画面へ露出し、盤面と操作部が離れ、開始・結果・目標表示が弱いと判定した。これを受け、PR #16で次を実装・マージした。

- 通常画面をプレイヤー向け画面へ整理し、ビルド情報・技術診断・試遊レポートを`?debug=1`だけで表示する
- 得点、球数、残り球、進行、現在の状態、次の目標、戻り道を盤面上部へまとめる
- 開始オーバーレイと3球終了後の結果オーバーレイを追加する
- 盤面と左右フリッパー・発射操作を同じゲーム枠へ配置する
- 現在の目標ショットへ盤面上の目印を描く
- 安全・中核・危険ショットで、目標幅と制限時間を分ける
- 開始前のポインター・キーボード操作を受け付けず、開始ボタン後だけ操作できるようにする

この変更は、実際にフリッパーで狙って成功できること、左右ルートへ異なる判断理由があること、クライマックスが楽しいことを合格扱いにしない。

## 4.4 安全ショット操作因果パス

PR #16後に実装と試験を突合したところ、従来の物理統合試験は球を`L0`の入口、確認点、出口へ直接移動し、発射後の速度も直接与えていた。ブラウザ試験も、発射が盤面へ入ることとフリッパーが動くことを別々に確認していた。そのため、プレイヤー入力がショット結果へつながることを証明していなかった。

さらに、従来の`R0`センサーは発射位置`x = 8.05`を覆い、最大発射だけで入口、確認点、出口を正順通過できた。これはフリッパー操作なしの誤成功である。

PR #17〜#19の操作因果パスで、次を実装・確認した。

- `L0`を右フリッパーから左へ横断する下部軌道へ移す
- `R0`を右フリッパーから右上へ返す下部軌道へ移す
- 盤面内操作パネル専用の下部領域を確保し、球、フリッパー、下部安全ショットをボタンで隠さない
- 球の直接移動、速度の直接変更、成功イベントの直接生成を使わず、最大発射とPointer入力だけで成立させる
- 60Hz / 120Hzの各レートで、`L0` / `R0`それぞれ押下位置と保持時間を組み合わせた10個の固定入力条件を試し、8個以上を成功させる
- 発射だけ、または無関係な左フリッパーでは得点・進行を更新しない
- 成功後に得点100、進行`1 / 5`、次目標、戻り表示、物理ゲートを一緒に更新する
- 成功後の実球が`L0`は左、`R0`は右の対応フリッパー付近へ戻り、同側Pointer入力で実フリッパー衝突後に上向きへ再発射できることを60Hz / 120Hzで確認する
- Chromium / WebKitで画面上の発射とフリッパー操作からHUD更新まで確認する
- 320px / 390px / 430pxの縦画面で盤面と操作パネルが重ならず、盤面表示高470px以上を保つ

この自動確認の10条件は、同一の決定論的軌道に対する固定の押下位置と保持時間であり、10人または人間による10試行ではない。物理的な到達可能性と回帰耐性を証明するが、GAのプレイヤー観察値を通過扱いにしない。

### 4.5 中核戻りの実入力確認

安全ショット後の球が実際に通る下部戻り軌道へ、`L1` / `R1`のセンサー列を再配置した。発射と右フリッパーの入力に続けて、`R0→L1`または`L0→R1`が60Hz / 120Hzで成立し、得点350、進行`2 / 5`、次の危険ショット、戻りゲートまで更新されることを確認した。球の直接移動、速度変更、成功イベントの注入は行っていない。

この確認は中核入口までの技術因果を示すもので、上部の`L2` / `R2`、中央`C0` / `C1`、片側連打の支配性、iPhone Safariの体感を合格扱いにしない。また、L1/R1は現段階では下降戻り列であり、上向きの高リスク返球は別工程で調整する。

## 5. まだ判定していないこと

- 初見5人のうち4人以上が10秒以内に左右を理解するか
- 初見5人のうち4人以上が15秒以内に発射できるか
- 3〜5ゲーム後に成功率、狙い、次の練習方針が改善するか
- 片側連打だけで中心機能を完了できないか
- 3球の進行が長すぎず、結果へ到達したくなるか
- iPhone Safariでの表示、二本指、入力遅延、発熱、音、保持操作
- 仮得点と戻り再構成型が面白さへつながるか
- 成功後に同側フリッパーを操作して、球を上向きに再発射できるか（固定物理の再発射は自動確認済み。人の操作感は未判定）
- `L0` / `R0`を同じ右フリッパーの打つ時期で選ぶ方式が、初見にも左右の選択として伝わるか

これらは管理端末で、ユーザー本人が管理する対面試遊として記録する。未達の場合は、演出を足して隠さず、経路数、戻り、難度、案内、クライマックス条件を見直す。

## 6. 判定の扱い

自動ゲート通過は「3球の技術的な縦切りが再現可能」という意味に限る。Pagesの実配置確認はRun #16で完了したが、G3 / GA工程全体は、初見理解、反復時の上達、片側連打の支配性、端末上の操作感、中心体験の試遊記録を確認するまで完了扱いにしない。

操作因果パスはPR #17、対応フリッパーへの返球・同側実衝突はPR #18、同側入力後の固定物理による上向き再発射はPR #19でマージ済み。Pagesの実配置はRun #16で確認済みである。次は管理端末の人手試遊で、左右目標の理解、3球の継続、3〜5ゲーム後の上達、面白さを判定する。人手試遊、G4 / VS、本番素材、正式公開は別工程である。
