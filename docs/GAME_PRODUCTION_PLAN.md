## 1. この文書の役割

本書は、DOPPANを「動くピンボール」ではなく、スマホブラウザ上で明確な技能、判断、上達、作品固有の達成感を持つゲームとして完成させるための最上位計画である。

本書が正本となる内容:

- 制作目的
- 対象プレイヤー
- 作品方針
- 正式版1.0の範囲
- 制作段階とゲート
- 制作予算と中止条件
- 公開判断
- 公開後の成果

技術、数値、試遊、中心体験、GitHub Pages運用の詳細は各正本文書へ委ねる。

データ保存、個人アカウント、外部通信、ホスティングについて衝突がある場合は、[データ非保存・GitHub運用方針](./DATA_AND_HOSTING_POLICY.md)を優先する。

判断の優先順位:

1. 安全、権利、プレイヤーの公平性
2. プレイヤー体験
3. 作品固有の価値
4. 品質ゲート
5. 実装都合
6. 既に作った量

既に作った量は、品質不足や不要なデータ保存を受け入れる理由にしない。

## 2. 制作目的

### 2.1 主目的

DOPPANを、カメレオンJPの代表作候補として公開できる、縦持ちスマホ向けブラウザゲームへ完成させる。

代表作候補の条件:

- 公開URLを開くだけで遊べる
- 初見でも基本操作を理解できる
- 操作の上達が結果へ反映される
- 一枚の盤面を繰り返し攻略する価値がある
- 15秒程度の映像で固有の面白さを示せる
- 技術実験ではなく作品として紹介できる
- アカウント登録や記録保存がなくても一回の体験が完結する

### 2.2 補助目的

- スマホ向け2D物理ゲームの制作・試験基盤を作る
- AI支援の一人制作でも企画、実装、試遊、公開判断を分離する
- 将来再利用できる入力、物理、盤面データ、得点分析の設計を残す

ここでいう得点分析は、制作中の試遊と端末内診断に限る。正式版の利用者行動を外部収集する意味ではない。

### 2.3 主目的にしないもの

正式版1.0では次を主目的にしない。

- 直ちに収益化すること
- 毎週更新するライブサービス
- 多数盤面の運営
- 実機ピンボールの完全再現
- 3D表現そのもの
- ランキングだけで継続理由を作ること
- 個人アカウント、ログイン、名前登録
- 得点、戦績、履歴、プレイ回数の保存
- 広告、決済、有料機能、商取引
- 外部分析による利用者追跡

## 3. 作品の暫定的な約束

現段階の仮説:

> **発射強度を決め、左右のタッチで球を打ち返し、成功ショットで戻り道をつなぎ直す、縦持ちスマホ向けの技能型ピンボール。**

G2の仮設計として、戻り再構成型と固有動詞「つなぎ直す」を採用候補にした。G3 / GAの仮図形で、成功ショットが次の狙いと戻りを実際に変えるかを確認してから最終化する。

確定条件:

- ピンボール以外の固有価値が入る
- 実際の操作と矛盾しない
- 代表的な仕組みを説明している
- 市場比較で他作品との差を示せる
- 正式版1.0の範囲で証明できる
- 15秒の動画で伝えられる

「覚醒」「爽快」「派手」だけでは固有価値としない。

## 4. 対象プレイヤー

### 4.1 主対象

スマホで3〜8分程度の技能型ゲームを遊びたい人。ピンボール経験は問わない。

求める状態:

- インストールと会員登録なし
- 名前入力とログインなし
- 長い説明を読まずに開始
- 偶然だけでなく操作が結果へ反映
- 失敗理由を理解して改善
- 一回ごとに明確な終了
- 短時間でも上達を実感

### 4.2 副対象

ピンボール経験者、スコアアタック経験者、球の扱いと経路選択を練習したい人。

提供する価値:

- フリッパー位置とタイミングによる球筋の差
- 球を受けて狙い直す余地
- 安全、中核、危険ショット
- 成功後の戻りを含む経路設計
- 今回の得点内訳による自己改善

得点内訳は結果画面へ一時表示するが、自己最高や履歴として保存しない。

### 4.3 主対象にしない層

- 実機と同じ傾斜、部品、台揺らしを求める層
- 長時間の育成、収集、物語が主目的の層
- 版権や3D映像だけを期待する層
- リアルタイム対戦を最優先する層
- アカウント育成、ランキング履歴、端末間引き継ぎを求める層

## 5. ゲームデザインの五つの柱

1. **触った瞬間に返る**
2. **狙いが結果へ反映される**
3. **盤面を理解すると上達する**
4. **成功が段階的に高まる**
5. **公平に終われる**

これらは品質方針であり、DOPPAN固有の仕組みではない。固有性は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)で決める。

記録保存を継続理由にしない。一回の操作、判断、クライマックス、再挑戦の価値で反復を成立させる。

## 7. GitHub Pages方針

### 7.1 完成前

- GitHub Pagesをユーザー本人のiPhone確認に使用
- 完成前はURLをREADME、SNS、公開サイト、記事へ掲載・案内しない
- 本番ルートへ未完成ゲームを配置しない
- 確認ページは信頼済みブランチ一件だけ
- 検索除外を設定
- GitHub Pagesは公開URLであり、推測アクセスを完全には防げない
- 第三者へ確認URLを配布しない
- `main`への取り込みだけでは正式公開しない
- G7後の手動承認で正式公開

### 7.2 正式版1.0

- 無料の静的ブラウザゲームとして公開
- 個人アカウントなし
- 利用者データ収集なし
- 決済、広告、有料機能なし
- GitHub Actionsは開発、試験、ビルド、配置だけに使用
- 一日100人、200プレイを負荷想定とする
- 初回転送3MB、総容量10MBを目標とする
- 厳しい条件で月約60GBを想定する

GitHub Pagesの現行規約では、静的な個人・組織プロジェクトの紹介が主な用途であり、オンライン事業、電子商取引、商用SaaSを無料ホスティングする用途は認められていない。DOPPANはその禁止境界へ入らない構成を維持する。

詳細と停止条件は[データ非保存・GitHub運用方針](./DATA_AND_HOSTING_POLICY.md)と[公開・プレビュー・安全運用計画](./DEPLOYMENT_AND_SECURITY_PLAN.md)を正本とする。

### 8.1 意味のテーマ

- 盤面で完成させるもの
- ショットと進行の意味

- 配色
- 形状

- 固有名称
- 音楽・効果音
- 演出強度
- 公開画像

### 8.3 代表的な仕組み

```text
操作
→ 盤面変化
→ 次の判断
→ クライマックス
```

候補3案、比較、採用理由、不採用理由、見直し条件を記録する。

## 9. 正式版1.0の基本ルール

GA検証仕様として決定する。

### 9.1 ゲーム単位

- 1ゲーム3球
- 中央値3〜6分を仮目標
- 90パーセンタイル10分以内を仮目標
- 最終球だけ秘密に物理難度を変えない

### 9.2 球をまたぐ進行

一回のゲーム内で保持:

- 恒久進行
- 完成済み主要目標
- 基本倍率の恒久上昇
- クライマックス準備

球終了で解除:

- コンボ
- 制限時間付き倍率
- 一時案内
- 短時間モード
- 入力状態

ボールセーブ再発射では球数と進行を減らさない。

ゲーム終了、再挑戦、再読み込み、タブ終了後には、すべてのゲーム進行を消去する。

### 9.3 発射

- G1-Bで操作方式を比較
- GAで基本スキルショットを一つ検証
- 攻略価値、再現性、初見理解が不足すれば固定発射

### 9.4 中断、結果、端末設定

- 画面非表示では安全停止
- 再読み込み、タブ終了、強制終了では進行中ゲームを復元しない
- 得点、最高得点、得点内訳、戦績、履歴、回数を保存しない
- 結果画面には今回の得点と内訳だけを表示する
- 再挑戦時は新しい一回として初期化する
- 音、画面効果、高コントラスト、初回案内などの非個人設定だけを端末内保存してよい
- 設定保存が使えなくてもゲームを継続する
- 時間切り捨てなどで公正性を失った場合は、結果画面へ注意を表示できるが、そもそもゲーム記録は永続化しない

## 10. 一枚盤面の習熟

- 1ゲーム目: 入力、発射、安全ショット
- 2〜5ゲーム目: 球の受け方、中核ショット、球間進行
- 5〜10ゲーム目: 戻り、左右経路、危険ショット
- 10ゲーム以降: クライマックス、得点経路最適化
- 熟練後: 同じ到達を少ない失敗で再現

初回だけ面白く、理解後に選択がなくなる盤面は不合格。

保存された称号、連続日数、ランキング順位ではなく、プレイヤー自身が操作と盤面理解の変化を感じられることを価値とする。

## 11. 球受け・保持

絶対条件ではなく中心技能候補。

残す条件:

- 狙い直しで新しい判断が生まれる
- 初心者は知らなくても安全ショットを遊べる
- 常時の不自然な補正を必要としない
- 盤面速度を不自然に下げない
- 経験者が再現できる

分岐:

- 中心技能
- 上級技能
- 初回案内から除外
- 作品約束から除外

## 12. 正式版1.0の範囲

### 12.1 必須

- 安定した一盤面
- 安全、中核、危険、発射スキルショット
- 球を受けて狙い直す余地
- 一回のゲーム内で球をまたぐ進行
- 代表的な仕組み
- クライマックス1種類
- 得点と進行の理解
- 今回の得点と内訳を示す結果画面
- 音なし
- 点滅、粒子、画面揺れの軽減
- 高コントラスト
- 公開URL、操作説明、更新履歴
- WebGL非対応案内
- 不具合報告導線
- アカウント、名前、記録、外部分析を持たないこと

球の保持は、G1-BとGAで面白さを増すと確認できた場合だけ必須に残す。

### 12.2 可能な限り含める

- 基本練習3課題以内
- 今回の得点内訳
- 結果テキスト共有
- 音、画面効果、高コントラストなどの端末設定

### 12.3 正式版1.0へ含めない

- 個人アカウント
- ログイン
- 名前登録
- 最高得点、戦績、履歴、プレイ回数の保存
- ランキング
- 外部テレメトリー
- Supabaseまたは外部データベース
- 広告、決済、有料機能
- ゴースト、リプレイ

これらを将来追加する場合は、通常の小規模拡張として扱わず、データ方針、費用、規約、ホストを含む別計画とユーザー再承認を必要とする。

## 13. 制作予算

### 13.1 内容上限

- 意味のテーマ候補最大3件
- 代表的な仕組み候補3件
- GA全面作り直し最大2回
- VS 1案
- クライマックス1種類

- 音楽最大2状態
- 効果音イベント原則12種類以内

### 13.2 作業単位上限

| 段階 | 上限 |
|---|---|
| G1-A | 基盤PR 1件、終了後確認1件まで |
| G1-B | 物理試作PR 1件、修正2回まで |
| G2 | 1成果物群 |
| GA | 初期盤面PR 1件、全面再設計2回 |
| VS | 統合PR 1件、修正1回 |
| CCB | 最大4作業単位 |
| RC | 不具合修正のみ |

上限到達後に不合格なら、同じ設計を微調整し続けず、機能削減または計画再承認へ進む。

## 15. 試遊

試遊は[試遊実施手順](./PLAYTEST_PROTOCOL.md)を正本とする。

完成前は第三者へURLを配布しない。

原則:

- ユーザー本人が自分の端末で確認ページを開く
- 対面で端末を参加者へ渡す
- 試遊後に回収
- URLをメッセージ、QR、SNSで渡さない

見る内容:

- 初回発射
- 入力理解
- ショット試行と成功
- 球の視認性
- 落下場所
- 得点構成
- 公平感
- 終了後満足
- 次に改善したい行動
- 3〜5ゲーム後の上達

試遊レポートは端末内で生成し、自動送信しない。人数不足を成功扱いにしない。

## 19. 主要リスクと中止条件

| リスク | 早期兆候 | 対応 |
|---|---|---|
| 技術基盤が大きすぎる | 一PRでCIと物理を同時構築 | G1-A/Bへ分割 |
| 短いタップ消失 | 押下・解放が描画前に完了 | InputEventQueue |
| 二重ループ | PixiTickerと独自loop | 単一所有、HMR停止 |
| 球終了消失 | 非表示と落下が同時 | pendingTerminalEvents |
| 接触二重得点 | beginとpostSolve混同 | 用途別イベント |
| 物理命令不整合 | 開閉・破棄競合 | 競合表、上限超過停止 |
| Pages誤公開 | mainマージで本番更新 | G7手動公開のみ |
| URL拡散 | READMEやSNS掲載 | 完成前掲載禁止 |
| 古い保存仕様の再導入 | 自己最高、scoreキー、履歴が実装される | データ方針を優先し自動試験で禁止 |
| 設定へ個人情報が混入 | 名前、得点、日時、IDが設定型へ追加 | P1として停止、型と試験を修正 |
| GitHub Pages規約逸脱 | 決済、商取引、商用SaaS化 | 公開停止、機能削減またはホスト再設計 |
| Actions用途逸脱 | 実行時API、定期集計、配信網に使用 | ワークフロー停止、設計見直し |
| 帯域余裕低下 | 月70GB超見積もり、429、GitHub警告 | 素材削減、公開停止、移行計画 |
| 物理は正しいが面白くない | 球受け・狙いが不要 | 企画側撤退条件 |
| 盤面が部品一覧 | 戻りがない | G2停止 |
| 演出で弱さを隠す | 仮図形で面白くない | 本番素材停止 |
| 得点攻略が単調 | 一得点源集中 | 得点、戻り、進行再設計 |
| 性能不足 | 時間切り捨て反復 | 表示削減、結果へ公正性注意を表示 |
| 試遊証拠不足 | URL非配布で人数不足 | 証拠不足として残す |
| 権利不明 | 出所記録なし | 公開禁止 |
