## 1. この文書の役割

本書は、DOPPANを「動くピンボール」ではなく、スマホブラウザ上で明確な技能、判断、上達、作品固有の達成感を持つゲームとして完成させるための最上位計画である。

本書が正本となる内容:

- 制作目的
- 対象プレイヤー
- 作品方針
- 正式版1.0の範囲
- 制作段階とゲート
- 制作予算と中止条件
- 公開判断と公開後の成果

技術、数値、試遊方法、中心的な仕組みの詳細は、それぞれの正本文書へ委ねる。同じ内容を複数文書へ重ねて書かない。

判断が衝突した場合は、次の順で優先する。

1. 安全、権利、プレイヤーの公平性
2. プレイヤー体験
3. 作品固有の価値
4. 品質ゲート
5. 実装都合
6. 既に作った量

既に作った量は、品質不足を受け入れる理由にしない。

## 2. 制作目的

### 2.1 主目的

DOPPANを、カメレオンJPの代表作候補として公開できる、縦持ちスマホ向けブラウザゲームへ完成させる。

代表作候補とは、次を満たす作品を指す。

- 公開URLを開くだけで遊べる
- 初見でも基本操作を理解できる
- 操作の上達が結果へ反映される
- 一枚の盤面を繰り返し攻略する価値がある
- 15秒程度の映像で固有の面白さを示せる
- 技術実験ではなく、作品として紹介できる

この主目的は計画実行上の決定とする。変更する場合は、[意思決定記録](./DECISION_LOG.md)へ理由と影響を残す。

### 2.2 補助目的

- スマホ向け2D物理ゲームの制作・試験基盤を作る
- AI支援の一人制作でも、企画、実装、試遊、公開判断を分けられる工程を残す
- 将来再利用できる入力、物理、盤面データ、得点分析の設計を残す

### 2.3 主目的にしないもの

正式版1.0では次を主目的にしない。

- 直ちに収益化すること
- 毎週更新するライブサービス
- 多数の盤面運営
- 実機ピンボールの完全再現
- 3D表現そのもの
- ランキングだけで継続理由を作ること

## 3. 作品の暫定的な約束

現段階では次のように定義する。

> **発射強度を決め、左右のタッチで球を受け止めて狙い直し、正確なショットをつなぐほど盤面が変化する、縦持ちスマホ向けの技能型ピンボール。**

この文章はG2で確定する。確定条件:

- ピンボール以外の固有価値が入る
- 実際の操作と矛盾しない
- 代表的な仕組みを説明している
- 市場比較で他作品との差を示せる
- 正式版1.0の範囲で証明できる
- 15秒の動画で伝えられる

「覚醒」「爽快」「派手」だけでは固有価値としない。

## 4. 対象プレイヤー

### 4.1 主対象

スマホで3〜8分程度の技能型ゲームを遊びたい人。ピンボール経験は問わない。

求める状態:

- インストールと会員登録なしで始められる
- 長い説明を読まずに操作できる
- 偶然だけでなく操作が結果へ反映される
- 失敗理由を理解し、次の改善を選べる
- 一回ごとに明確な終了がある
- 短時間でも上達を感じられる

### 4.2 副対象

ピンボール経験者、スコアアタック経験者、球の扱いと経路選択を練習したい人。

提供する価値:

- フリッパー位置とタイミングによる球筋の差
- 球を受けて狙い直す余地
- 安全、中核、危険ショットの使い分け
- 成功後の戻りを含むショット設計
- 得点内訳による自己改善

### 4.3 主対象にしない層

- 実機と同じ傾斜、部品、台揺らしを求める層
- 長時間の育成、収集、物語を主目的にする層
- 版権や3D映像だけを期待する層
- リアルタイム対戦を最優先する層

## 5. ゲームデザインの五つの柱

すべての仕様は、次のどれを強めるか説明できなければならない。

1. **触った瞬間に返る**: 入力とフリッパー反応を直結させる
2. **狙いが結果へ反映される**: 主要得点は選んだショットと精度から生む
3. **盤面を理解すると上達する**: 安全目標から経路、戻り、連続ショットへ深まる
4. **成功が段階的に高まる**: 通常接触とクライマックスを同じ強さにしない
5. **公平に終われる**: 終了、再挑戦、結果確認を同じ強さで選べる

これらは品質方針であり、DOPPAN固有の仕組みではない。固有性は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)で別に決める。

## 6. 制作段階

工程名に「MVP」を使わない。

| 段階 | 略称 | 目的 | 公開扱い |
|---|---|---|---|
| 技術試作 | TP | 入力と物理が成立するか確認 | 非公開 |
| グレー版アルファ | GA | 仮図形で中心的な仕組みと得点が面白いか確認 | 限定試遊 |
| 縦切り版 | VS | 最も危険な統合部分を本番相当で確認 | 限定試遊 |
| コンテンツ完成版 | CCB | 一盤面と主要機能が一通り入る | 非公開または限定公開 |
| リリース候補版 | RC | 公開条件の最終確認 | 限定公開 |
| 正式版1.0 | v1.0 | G7承認後に一般公開 | 一般公開 |

現在地は[制作状況](./PRODUCTION_STATUS.md)、数値条件は[品質ゲート定義](./QUALITY_GATES.md)を正本とする。

## 7. テーマと中心的な仕組み

### 7.1 意味のテーマ

GAを作る前に決める。

- 世界観の仮説
- プレイヤーが行う固有動詞
- 盤面で完成させるもの
- ショットと進行の意味
- クライマックスの仮説

### 7.2 表現のテーマ

GAの面白さ判定後、VS開始時に固定する。

- 配色
- 形状
- アート様式
- 固有名称
- 音楽と効果音
- 演出の強さ
- 公開画像

### 7.3 代表的な仕組み

G2では[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)の候補を比較し、次を一組で決める。

```text
操作
→ 盤面変化
→ 次の判断
→ クライマックス
```

G2成果物には、候補3案、比較点、採用理由、捨てた理由、見直す条件を含める。

## 8. 正式版1.0の基本ルール

以下はGA検証仕様として決定する。試遊結果により見直せる。

### 8.1 ゲーム単位

- 1ゲーム3球
- 目標時間は中央値3〜6分
- 90パーセンタイル10分以内
- 最終球だけ秘密に物理難度を変えない

### 8.2 球をまたぐ進行

保持する:

- 盤面の恒久進行
- 完成済み主要目標
- 基本倍率の恒久上昇
- クライマックス準備状況

球終了で解除する:

- コンボ
- 制限時間付き倍率
- 一時的な案内
- 短時間モード
- 入力状態

ボールセーブ再発射では球数も進行も減らさない。

### 8.3 発射

- TPで操作方式を比較
- GAでは発射強度を使う基本スキルショットを一つ入れる
- 攻略価値、再現性、初見理解のいずれかが不足する場合は固定発射へ簡略化

### 8.4 中断と保存

- 画面非表示では自動ポーズ
- 再読み込み、タブ終了、強制終了では進行中ゲームを復元しない
- 最高得点と設定はゲーム終了時に保存
- 保存の永久保持を保証しない

技術上の正本は[推奨実装計画書](./IMPLEMENTATION_PLAN.md)とする。

## 9. 習熟と一枚盤面の価値

一枚の盤面を繰り返す価値は、初回理解だけで判断しない。

- 1ゲーム目: 入力、発射、安全ショット
- 2〜5ゲーム目: 球の受け方、中核ショット、球間進行
- 5〜10ゲーム目: 戻り、左右経路、危険ショット
- 10ゲーム以降: クライマックス到達、得点経路最適化
- 熟練後: 同じ到達を少ない失敗で再現

詳細と合否は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)と[品質ゲート定義](./QUALITY_GATES.md)で管理する。

## 10. 球の保持の位置付け

球の保持は中心技能候補であり、絶対条件ではない。

残す条件:

- 狙い直しによって新しい判断が生まれる
- 初心者が使わなくても遊べる
- 常時の不自然な補正が不要
- 経験者が再現できる

成立しない場合は、物理調整だけでなく次を選べる。

- フリッパー周辺を再設計
- 上級技能へ下げる
- 初回案内から外す
- 作品約束と正式版必須から外す

詳細な分岐は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)を正本とする。

## 11. 正式版1.0の範囲

### 11.1 必須

- 安定した1盤面
- 発射と最低3種類の意味あるショット
- 球をまたぐ進行
- 代表的な仕組み
- 象徴的なクライマックス1種類
- 得点と進行の理解
- 端末内最高得点
- 音なし
- 点滅、粒子、画面揺れの軽減
- 高コントラスト
- 公開URL、操作説明、更新履歴
- WebGL非対応案内
- 不具合報告導線

球の保持は、G1とG3で面白さを増すと確認できた場合のみ必須に残す。

### 11.2 可能な限り含める

- 基本練習3課題以内
- 得点内訳
- 結果テキスト共有
- 事実に基づく簡単なプレイ集計

### 11.3 公開後でもよい

- 詳細な改善提案
- 共有画像
- 詳細練習
- ゴースト
- リプレイ
- ランキング
- 外部テレメトリー

公開後候補を理由にv1.0を延期しない。

## 12. 制作予算

一人制作で完成させるため、作業量を先に制限する。

### 12.1 内容上限

- 意味のテーマ候補: 最大3件
- 代表的な仕組み候補: 3件
- GA全面作り直し: 最大2回
- VS: 1案
- 正式版クライマックス: 1種類
- 練習課題: 最大3件
- 本番盤面: 1枚
- 本番音楽: 最大2状態
- 効果音イベント: 原則12種類以内
- 同一重大問題の調整: 2サイクル

### 12.2 作業単位上限

| 段階 | 上限の目安 |
|---|---|
| TP | 基盤PR 1件 + 修正2回 |
| G2 | 市場・中心体験・ショット設計を1成果物群 |
| GA | 初期盤面PR 1件 + 全面再設計2回 |
| VS | 統合PR 1件 + 修正1回 |
| CCB | 盤面、表現、UI・設定、完成調整の最大4作業単位 |
| RC | 不具合修正のみ。新機能禁止 |

上限到達後に不合格の場合、同じ設計を微調整し続けず、機能削減または計画再承認へ進む。

## 15. 公開後の成果

- 初見理解
- 公平感

## 17. 制作ゲート

### G0: 制作目的

通過条件:

- 主目的、補助目的、非目標、対象プレイヤーが決定

### G0.5: 市場・名称

通過条件:

- 8作品以上を比較
- DOPPANとの差を一文で説明
- 正式名称の扱いを決定

### G1: 技術試作

通過条件:

- [品質ゲート定義](./QUALITY_GATES.md)のTP条件を満たす
- 発射、入力、衝突、球の受け方を計測
- 保持を中心技能に残すか仮判断

### G2: 中心体験とショット設計

成果物:

- 意味のテーマ
- 代表的な仕組み3候補と採用理由
- 固有動詞
- クライマックス仮説
- 習熟段階表
- 左右ショットマップ
- 仮得点

通過条件:

- 操作、盤面変化、次の判断、クライマックスが一続きで説明できる
- 盤面部品を置く前に左右の狙いと戻りを説明できる

### G3: グレー版アルファ

通過条件:

- GA数値条件を満たす
- 初見試遊と3〜5ゲーム後の上達確認を実施
- 代表的な仕組みが表示だけでなく判断を変える
- 全面作り直し条件に該当しない

### G4: 縦切り版

固定範囲は[中心体験・表現計画](./CORE_EXPERIENCE_PLAN.md)に従う。

通過条件:

- 最も危険な統合部分が本番相当で成立
- 15秒で固有価値を示せる
- 軽減設定と復旧を含む
- 素材量と容量を見積もれる

### G5: コンテンツ完成版

通過条件:

- 一盤面、クライマックス、設定、保存、結果が揃う
- CCB品質ゲートを満たす

### G6: リリース候補版

通過条件:

- 新機能を止め、不具合修正だけを行う
- RC品質ゲート、権利台帳、公開素材を満たす

### G7: 公開承認

確認:

- GitHub Pages本番URL
- 保存と更新
- WebGL・音声復旧
- 共有代替
- ロールバック
- 名称と素材権利
- 公開後の監視範囲

ユーザー本人の承認後に一般公開する。

### G8: 正式版1.0

一般公開コミットへ`v1.0.0`相当の版を付ける。

## 18. 主要リスクと中止条件

| リスク | 早期兆候 | 対応 |
|---|---|---|
| 物理は正しいが気持ちよくない | 球を受けられない、狙いが再現しない | G1で2回調整し、方式または約束を見直す |
| 保持が目的化する | 初心者が使えない、全体が不自然 | 上級技能化または必須から除外 |
| 固有性がない | 説明が一般的なスマホピンボール | G0.5とG2を再実施 |
| 盤面が部品一覧になる | 戻りと次判断がない | 部品配置を停止しショット設計へ戻る |
| 演出で弱さを隠す | 仮図形で面白くない | 本番素材制作を停止 |
| 理解後に浅い | 3〜5ゲーム後も行動が増えない | 習熟と代表的な仕組みを再設計 |
| 得点が単調 | 一つの得点源へ集中 | 得点、戻り、進行を再設計 |
| 正式版範囲が膨張 | 公開後候補が必須へ移る | 11章へ戻し、ユーザー再承認 |
| 試遊者を集められない | 募集経路が機能しない | 限定公開と遠隔手順へ切り替える |
| 名称・素材権利が不明 | 確認記録がない | 公開禁止 |
